# macOS 개발 경계와 검증

이 문서는 제품 경계와 실행 검증을 다루며 특정 아키텍처를 강제하지 않는다.
코딩 스타일은 [Swift 코딩 컨벤션](swift-coding-convention.md)을 따른다.

## 리버스 엔지니어링 원칙

- 원본 `~/Desktop/ai-run`은 읽기 전용이다. 읽고 문서화하되 수정하지 않는다.
- 제품 동작은 원본과 같게 유지한다. 코드를 그대로 복사하지 않고 파일별 동작을 문서화한 뒤 설계에 따라 다시 구현한다.
- 원본의 외부 의존(로그 경로, 캐시 포맷, 훅, 비공개 응답 형식)은 문서에 근거와 함께 기록한다.
- 원본의 버그로 보이는 동작은 임의로 고치거나 따라 하지 않고 명세에 기록한 뒤 결정한다.
- 동등성은 기존 앱과 새 앱을 나란히 실행해 기능 체크리스트로 대조한다.

## 검토할 경계

- 메뉴바 창의 열기, 닫기, 포커스, 상태 유지는 실제 macOS에서 확인한다.
- 파일 감시, 로그 파싱, 사용량 계산 같은 순수 로직은 UI와 분리해 단위 테스트한다.
- 비동기 작업의 취소, 재진입, 중복 실행을 검토한다. 모든 객체를 일괄 `@MainActor`로 만들지 않는다.
- 외부에서 읽어 온 데이터(로그, 캐시, 응답)는 미검증 입력이다. 형식 오류와 부분 손상을 코드에서 처리한다.
- 시간과 시간대, 현재 시각에 의존하는 로직은 기준 시점을 주입받게 해서 테스트 가능하게 한다.
- 권한 거부, 파일 없음, 잘린 로그, 실행 중이 아닌 외부 앱 같은 실패 경로를 검토한다.
- 테스트는 합성 데이터와 대체 구현을 우선한다. 사용자의 실제 세션 로그를 테스트 입력으로 커밋하지 않는다.
- 사용자 환경의 파일을 수정하는 동작(설정, 훅 설치 등)은 테스트 준비 과정에서 실행하지 않는다.

## 빌드와 테스트

Swift Package 기반이며 패키지는 `apps/macos`에 있다. CI 구성은 [CI와 릴리스 운영](../ci.md)을 따른다.

```bash
cd apps/macos
swift build
swift test
```

- 테스트 타깃이 없으면 `swift test`의 통과는 의미가 없다. 테스트가 없다는 사실을 보고에 밝힌다.
- 앱 번들은 `apps/macos/scripts/build-app.sh`로 만든다. 설치와 실행은 `install-app.sh`가 따로 맡는다.
- 빌드 통과만으로 파일 접근, 알림, 외부 앱 연동 같은 실제 동작을 검증했다고 하지 않는다.
- 실기기 검증에서는 macOS와 Xcode 버전, 대상 외부 앱과 버전을 기록한다.
- 코드 서명, 공증, 배포 설정은 별도 배포 작업이다.

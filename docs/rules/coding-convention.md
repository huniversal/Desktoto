# 코딩 컨벤션

공통 원칙과 적용 경로의 기준이다. 구체적인 구문, 이름, 상태 규칙은 언어별 문서에 둔다.

## 적용 범위

| 대상 | 적용 규칙 |
| --- | --- |
| Swift, SwiftUI, AppKit 소스 | [Swift 코딩 컨벤션](swift-coding-convention.md) |
| 브랜치, 커밋, PR, 라벨 | [Git 컨벤션](git-convention.md) |
| 제품 경계, 권한, 실행 검증 | [macOS 개발 기준](macos-development.md) |

## 공통 원칙

- 사용 지점에서 의도가 드러나는 이름을 쓴다. 의미 없는 축약이나 `data`, `temp`만으로 역할을 감추지 않는다.
- 바꿀 필요가 없는 값은 불변 선언을 우선하고, 실제 상태 변경에만 가변 선언을 쓴다.
- 값, 상태, 부작용의 소유 위치를 명확히 한다. 중복 상태를 만들어 두 곳에서 갱신하지 않는다.
- 도메인 로직은 해당 기능에 둔다. 두 번 쓰였다는 이유만으로 공용 계층을 만들지 않는다. 다만 두 개 이상의 기능에서 실제로 쓰이는 로직은 공용 모듈로 옮긴다.
- 파일 시스템, 프로세스, 시간, 네트워크 같은 외부 경계는 프로토콜 뒤에 두어 테스트에서 대체할 수 있게 한다.
- 컴포넌트는 재사용을 전제로 설계한다. UI 컴포넌트에는 비즈니스 로직을 넣지 않는다.
- 기존 코드로 해결되는 단순한 작업에 새 패턴, 추상화, 라이브러리를 강제하지 않는다.
- 수정, 제외, 정렬되는 목록은 안정적인 식별자를 쓴다. 위치를 항목의 정체성으로 취급하지 않는다.
- 오류, 권한, 취소, 부분 성공을 정상 결과로 숨기지 않는다.
- 비밀 값과 개인 데이터를 로그, 공유 문서, Git에 남기지 않는다. 검증 예시는 합성 데이터를 쓴다.
- 비직관적인 제한이나 공개 계약은 이유를 문서화한다. 코드 내용을 반복하는 주석은 늘리지 않는다.
- 수정한 파일은 그 파일의 기존 스타일을 따른다. 무관한 파일을 일괄 재포맷하지 않는다.
- 리버스 엔지니어링 중 발견한 원본의 버그나 불명확한 동작은 그대로 옮기지 않고 명세에 기록한 뒤 결정한다.

## 형식

들여쓰기는 Swift 4칸, 그 외 2칸이다. 문자 인코딩은 UTF-8, 줄바꿈은 LF다.
자동 포맷터와 린터, Git 훅은 도입을 합의하기 전까지 추가하지 않는다.

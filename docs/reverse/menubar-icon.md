## 상태별 모습

### 달리기 (24프레임)

- 한 바퀴를 24등분한다. `progress = phase / 24`, `originX = progress * 12`. 마지막 프레임이 첫 프레임과 겹치지 않는다.
- 다리는 3프레임마다 교대한다(`legStep = phase / 3`, 짝수이면 A, 홀수이면 B). 한 바퀴에 8번 교대하며 짝수라서 바퀴 끝에서 어긋나지 않는다. 그래서 원본 주석은 한 바퀴 프레임 수가 3의 배수여야 한다고 적는다.
- 위아래는 `originY = 2 * (0.5 + 0.5 * cos(pi * legStep))`. 다리 교대에 맞춰 낮은 자세와 높은 자세를 오간다.
- 속도선 3개를 캐릭터 뒤에 그린다(행 오프셋, 길이, 캐릭터와의 간격 = (2, 7, 3), (6, 4, 4), (10, 7, 3), 두께 2칸). 캔버스 왼쪽 밖으로 나가는 부분은 그리지 않는다. 색은 흰색(밝기 0.8, 투명도 0.9)이다.
- 배지는 캐릭터와 함께 가로로 따라가지만 위아래 흔들림은 따라가지 않는다.

### 서 있기

가운데(`originX = 9`)에 가만히 서 있다. 다리 길이 4, 흔들림 없는 높이(`originY = 2`)다.

### 잠든 모습 (6프레임, 0.6초 간격)

- 서 있는 자리에서 몸이 1칸 내려앉고(`originY = 3`) 눈이 한 줄이다.
- 배지 자리에 z가 떠오른다. 작은 z는 4x4, 큰 z는 5x5이며 색은 흰색 투명도 0.85다. 좌표는 배지 자리 왼쪽과 위쪽 기준 칸이다.

| 프레임 | 작은 z(열, 행) | 큰 z(열, 행) |
| --- | --- | --- |
| 0 | (0, 11) | 없음 |
| 1 | (0, 9) | 없음 |
| 2 | (0, 9) | (2, 3) |
| 3 | (0, 9) | (2, 3) |
| 4 | 없음 | (2, 2) |
| 5 | 없음 | 없음 |

- 확인하지 않은 완료 점이 있으면 z 대신 점을 같은 자리에 그린다.
- 잠든 모습은 승인 대기 배지를 그리지 않는다. 잠듦 조건이 대기 없음을 포함하므로 실제로는 겹치지 않는다.

### 폭죽 (24프레임, 약 1초)

- 서 있는 모습이나 달리는 모습 뒤에 한 번 재생한다. 이미 그려진 이미지 위에 합성하지 않고, 새 캔버스에 폭죽을 먼저 그리고 그 위에 기존 이미지를 덮는다.
- `progress = frame / 23`, `eased = 1 - (1 - progress)^2`, `alpha = max(0, 1 - progress^2.4)`.
- 알갱이 14개. 각도는 `2 * pi * index / 14 + 0.3`이고 도달 거리는 인덱스에 따라 (19, 15, 11)을 돈다. 반지름은 8에서 도달 거리까지 `eased`로 늘어난다.
- 위치는 캔버스 가로 가운데(21칸)와 세로 9칸이 중심이며 세로 방향은 0.5배로 눌리고 `4 * progress^2`만큼 아래로 처진다.
- 알갱이 크기는 `progress < 0.45`이면 3칸, `< 0.8`이면 2칸, 그 뒤는 1칸이다.
- 색은 분홍, 노랑, 하늘, 연보라, 흰색 5가지를 순환하고 알갱이마다 `alpha`를 곱한다.
- `progress < 0.2`일 때 중심에 4x4 흰 섬광을 그리고 투명도는 `1 - progress / 0.2`다.
- 마지막 프레임(23)은 `alpha`가 0이라 알갱이가 보이지 않는다.

### 배지

- 위치: 캐릭터 왼쪽 끝 + 24칸 + 1칸, 위쪽은 0행.
- 승인 대기 물음표(5x7)가 확인하지 않은 완료 점(4x4)보다 우선한다. 사람이 해야 할 일이 더 급하기 때문이다.
- 물음표 격자(1이 칠해짐): `01110`, `10001`, `00001`, `00110`, `00100`, `00000`, `00100`.
- 색: 물음표 (1.00, 0.80, 0.35), 완료 점 (0.68, 0.52, 1.00). 완료 점은 패널 카드의 점과 같은 색이다. 물음표 색은 패널 승인 알약(1.00, 0.78, 0.30)과 값이 다르다.

## 이미지 만들기와 캐시

- 그리기 클로저로 만든 `NSImage`는 화면에 쓰일 때마다 다시 그려지므로, 한 번만 그려서 `CGContext`의 비트맵(`premultipliedLast`, `DeviceRGB`)으로 저장한다. 결과는 `isTemplate = false`다.
- 비트맵 배율은 만들 때의 `NSScreen.main?.backingScaleFactor ?? 2`다. 이미지를 만든 뒤 다른 배율의 화면으로 옮기면 흐려질 수 있다(원본의 한계, 확인하지 않음).
- 그리기 좌표는 위쪽이 0이며 컨텍스트를 뒤집어서 맞춘다.
- `AppDelegate`는 서 있기 1장, 달리기 24장, 잠듦 6장을 필드로 들고 있다. 확인하지 않은 완료 여부나 승인 대기 여부가 바뀔 때(`applyIconState`)와 색상 모드가 바뀔 때만 모두 다시 만든다. 시작할 때는 기본 값으로 한 번 만들고, 시작 직후 `rebuildImages()`를 한 번 더 호출한다(80행).
- 폭죽은 캐시하지 않는다. 재생되는 프레임마다 기존 이미지 위에 새 비트맵을 합성한다.

## 갱신 주기와 24fps의 근거

| 상태 | 갱신 | 상수 |
| --- | --- | --- |
| 달리기, 폭죽 | 1/24초마다 이미지를 바꿔 끼움 | `RUNNING_FRAME_INTERVAL`, `RUNNING_PHASE_COUNT = 24`, `FIREWORK_FRAME_COUNT = 24` |
| 잠듦 | 0.6초마다 | `SLEEP_FRAME_INTERVAL`, `SLEEP_FRAME_COUNT = 6` |
| 서 있기 | 타이머 없음. 상태가 바뀔 때 한 번 설정 | |

원본 주석이 밝힌 근거(2026-11-03 확인):

- 움직임을 약 1pt 단위로 잘게 쪼개 한 바퀴를 24프레임으로 그리고, 초당 24번 갱신한다. 한 바퀴가 1초다.
- 메뉴바 아이콘을 바꿀 때마다 시스템(`NSStatusItem`)이 스냅샷을 다시 만들기 때문에 갱신 횟수가 CPU 사용량을 좌우한다. 원본 작성자는 초당 40번으로 올렸을 때 CPU를 20% 넘게 썼다고 주석에 적었다.
- 그래서 비트맵을 미리 만들고(그리기 비용 제거), 갱신은 24fps로 제한한다(스냅샷 비용 제한).

이 CPU 수치는 원본 작성자의 주석이며 이 저장소에서 직접 측정하지 않았다. #9에서는 근거로 기록만 하고, 실제 비교 측정은 앱이 조립되는 #11에서 원본과 나란히 실행해 확인한다.

## 상태 선택 (`AppDelegate`)

`applyIconState`의 분기는 다음과 같다. 타이머와 판정 입력은 #11이 맡고, #9는 "무엇을 보여 줄지"의 순수 규칙만 구현한다.

1. 확인하지 않은 완료 여부나 승인 대기 여부가 바뀌었으면 이미지를 다시 만든다.
2. 달리는 세션이 있거나 폭죽이 재생 중이면 잠듦 타이머를 멈추고 달리기 타이머를 켠다. 달리기 타이머는 매 틱마다 달리기 프레임 번호를 1 올리고(`% 24`), 이미지는 달리는 세션이 있으면 달리기 이미지, 없으면 서 있는 이미지를 쓴다. 폭죽이 재생 중이면 그 이미지 뒤에 폭죽을 합성하고 프레임을 1 올린다. 마지막 프레임 뒤에 폭죽이 끝나며, 달리는 세션이 없으면 타이머를 멈추고 서 있는 모습으로 돌아간다.
3. 그렇지 않으면 달리기 타이머를 멈추고, 잠든 상태이면 잠듦 타이머를 켜서 z를 0.6초마다 바꾼다. 아니면 서 있는 모습이다.

상태 입력(`handlePollTick`, 1초 폴링):

- 달리는 세션 수는 `running`이면서 승인 대기가 아닌 세션이다. 승인 대기 세션은 달리는 수에서 뺀다.
- 승인 대기 여부는 대기 세션이 하나라도 있는지다.
- 잠듦은 달리는 세션 없음, 승인 대기 없음, 폭죽 없음이며 마지막 활동 후 600초(`AIRUN_SLEEP_AFTER` 환경 변수로 초 단위 변경 가능)가 지난 상태다. 마지막 활동은 달리기, 승인 대기, 완료가 있었던 시각이며 시작 시각부터 센다.
- 폭죽은 진행 중이던 세션이 정상 종료되었고 승인 대기가 아닐 때 시작한다. 완료 점은 패널이 닫혀 있는 동안 끝난 세션이 있을 때 붙는다.

- 그림 캐릭터(치이카와, 하치와레, 우사기)는 원작 GIF에서 뽑아 배경을 지운 프레임을 애니 장면 배경 위에 그린다. 메뉴바 높이(노치 화면은 화면에서 잰 값)로 그리고 위아래 여백은 1pt다.
- 그림 캐릭터는 시선, 표정, 쉬는 동작을 하지 않고, 대기 중에는 대기 클립 여러 개를 50ms 간격으로 돌리다가 최소 4초 뒤 클립이 끝날 때 다른 클립으로 무작위로 바꾼다.
- 작업 중에는 상반신이 캔버스 높이를 채우도록 확대한다. 치이카와는 오른쪽으로 이동하며 들판이 흘러가고, 하치와레와 우사기는 제자리에서 춤춘다(하치와레는 원본 GIF 속도에 맞춰 절반 주기).
- 위 #61의 "외부 캐릭터 이미지를 쓰지 않는다"는 Claude 캐릭터에 해당한다. 그림 캐릭터는 원작 자료를 쓴다.

## 원본 특이점과 결정이 필요한 점

[macOS 개발 기준](../rules/macos-development.md)에 따라 원본의 의심스러운 동작은 임의로 고치지 않고 기록만 한다.

- 달리기 바퀴가 돌아올 때 위치가 오른쪽 끝(약 11.5칸)에서 왼쪽 끝(0칸)으로 한 번에 돌아간다. 반복 동작의 일부로 보이며 유지한다.
- 이미지 배율이 만들 때의 메인 화면 값으로 고정된다(위 "이미지 만들기와 캐시").
- 물음표 색이 패널 승인 알약 색과 값이 다르다.
- 폭죽을 재생하는 동안 매 프레임 새 비트맵을 만든다. 하루에 몇 번 나오지 않아 영향은 작아 보이지만 측정하지 않았다.
- 원본의 보정 색(`calibrated`)을 `DeviceRGB` 컨텍스트에 그려서 색 값이 바뀐다. #9의 픽셀 검사에서 확인한 값은 물음표 (1.00, 0.80, 0.35)가 (1.00, 0.83, 0.42)로, 완료 점 (0.68, 0.52, 1.00)이 (0.74, 0.61, 1.00)으로 칠해진다는 것이다. 패널의 점은 `Color(nsColor:)`로 같은 값을 쓰므로 메뉴바 점이 패널 점보다 살짝 밝게 보일 수 있다. 새 구현도 같은 경로로 그려 원본과 같은 결과를 낸다.

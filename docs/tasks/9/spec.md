## 목적

메뉴바 아이콘으로 세션 상태(서 있음, 달림, 잠듦, 완료 폭죽, 완료 점, 승인 대기 물음표)를 알리는 픽셀 캐릭터를
원본과 같은 모습과 움직임으로 만든다. 그리는 로직과 프레임 계산, 상태 선택을 분리해
UI 없이 단위 테스트할 수 있게 하고, 비트맵을 미리 만들어 두어 CPU 사용을 억제한다.

## 작업 범위

### 포함

- 24x17칸 픽셀 캐릭터 격자(몸통, 팔, 눈, 다리)와 포즈별 모양 정의, 그리기
- 상태별 이미지: 서 있기, 달리기(24프레임), 잠든 모습(6프레임의 z 애니메이션), 세션 종료 폭죽(24프레임)
- 배지: 확인하지 않은 완료 점과 승인 대기 물음표(물음표 우선), 배지 자리를 항상 확보하는 캔버스
- 비트맵 이미지 묶음과 다시 만드는 조건(색상 모드나 배지가 바뀔 때만), 프레임 주기 상수
- 원본의 24fps 판단 근거 문서화
- 색상 모드(흰색, 컬러) 반영
- 격자, 프레임 계산, 상태 선택, 배지 우선순위, 캐시 무효화, 색 반영의 단위 테스트
- `docs/reverse/menubar-icon.md` 작성, `docs/architecture.md`와 `docs/reverse/overview.md`의 해당 항목 갱신

### 제외

- 타이머 실행, 폴링 틱, 완료와 대기 감지, 600초 잠듦 판정, 소리, 알림, `NSStatusItem` 연결 (#11 앱 조립)
- 패널 View와 패널 모델 (#10), 설정 저장 (#8)
- 원본 소스 변경, 앱 설치, 배포, CI 변경
- 명세 선행 커밋 이외의 요청되지 않은 커밋, push, PR과 merge

## 설계 결정

- 파일 구조: `apps/macos/Sources/MenuBarIcon/`에서 순수 계산과 AppKit 그리기를 나눈다. 세부 파일 이름은 구현 시 역할에 맞춰 정한다.
  - 순수 계산(AppKit 미사용, `Sendable` 값 타입): 격자와 포즈 정의, 달리기 프레임 계산, z 프레임 표, 폭죽 알갱이 계산, 배지 선택, 상태에서 보여 줄 프레임 선택과 프레임 진행
  - AppKit: 사각형 목록을 비트맵으로 칠하는 그리기, 상태별 이미지 생성, 이미지 묶음(캐시)
- 상태 선택과 그리기의 경계: 앱이 판정한 상태(달리는 세션 있음, 잠듦, 폭죽 프레임, 확인하지 않은 완료, 승인 대기, 색상 모드)를
  값으로 받아 "어떤 프레임을 보여 줄지"를 순수 함수로 고르고, 프레임 번호를 한 칸 진행하는 규칙(달리기 `% 24`, 잠듦 `% 6`, 폭죽 종료)도 이 모듈의 값 타입이 맡는다.
  이 모듈은 타이머를 만들지 않는다. 달리기 24fps, 잠듦 0.6초, 폭죽 24프레임 같은 주기는 상수로 노출하고 실행은 #11이 맡는다.
- 의존: `Domain`, `DesignSystem`만 쓰고 `Boundaries`는 쓰지 않는다(아키텍처 의존 규칙 2). 현재 `Package.swift`의 `MenuBarIcon` 의존과 같다. 시간과 파일 접근이 없으므로 `TimeSource`도 쓰지 않는다.
- 상태와 동시성: 값 타입과 순수 함수는 `Sendable`이다. `NSImage`는 `Sendable`이 아니므로 이미지 묶음은 `@MainActor`로 격리해 메뉴바를 갱신하는 쪽과 같은 곳에서 소유한다. 모든 타입을 일괄 `@MainActor`로 만들지 않는다.
- 비트맵 배율: 원본은 이미지를 만들 때 `NSScreen.main`의 배율(없으면 2)로 고정한다. 새 구현은 배율을 인자로 받아 테스트에서 고정할 수 있게 하고, 앱은 원본과 같은 값을 넘긴다.
- 캐시(원본 동작 유지): 서 있기 1장, 달리기 24장, 잠듦 6장을 미리 만들어 두고 색상 모드나 배지가 바뀔 때만 모두 다시 만든다. 폭죽은 원본처럼 재생 중인 프레임마다 기존 이미지 뒤에 합성한다.
- 색: 컬러 몸 색 `#DD8B70`과 완료 점 보라를 포함해 캐릭터를 그리는 색은 모두 `MenuBarIcon` 안에 그리기 정의로 둔다. 이미 끝난 `DesignSystem`(#3)은 수정하지 않는다. 색상 모드 입력은 `DesignSystem`의 `ColorMode`를 쓴다. 완료 점 보라는 패널의 `DSColor.finishedDot`과 같은 값을 유지하고, 패널(#10)과 값이 어긋나지 않게 확인한다. 원본의 물음표 색(1.00, 0.80, 0.35)은 패널의 승인 알약 색(1.00, 0.78, 0.30)과 값이 다르며, 동등성을 위해 원본 값을 유지한다.
- 예외 처리: 범위를 벗어난 프레임 번호는 원본처럼 나머지 연산(`%`)으로 감싸 안전하게 처리하고, 비트맵 컨텍스트를 만들지 못하면 원본처럼 빈 이미지를 반환한다. 이 두 경로를 테스트로 고정한다.
- 테스트: `Package.swift`에 `MenuBarIconTests`를 추가한다. Swift Testing을 쓰고, 합성 입력과 메모리 안의 비트맵만 쓴다. 이미지 픽셀 검사는 배율을 고정해 일정한 좌표의 색을 읽는다. 사용자 환경의 파일은 읽거나 쓰지 않는다.
- 원본에서 이어받을 값: 캔버스 42x20칸(트랙 36칸과 배지 6칸), 한 칸 1pt, 달리기 이동 폭 12칸, 한 바퀴 24프레임, 다리 교대 3프레임마다, 위아래 흔들림 최대 2칸. 전체 값은 `docs/reverse/menubar-icon.md`에 둔다.

## 완료 조건

- AC-1: 격자 정의가 원본과 같다. 캐릭터 24x17칸, 몸통 18x12, 팔 3x3(왼쪽 0열, 오른쪽 21열), 눈 2x3 두 개, 다리 4개(2칸 폭, 열 4, 7, 15, 18)와 포즈별 다리 길이와 팔 높이 차이가 일치한다.
- AC-2: 달리기 프레임 계산이 원본과 같다. 24프레임이 한 바퀴를 이루고 위치는 0에서 12칸 미만까지 등분하며, 다리는 3프레임마다 교대해 한 바퀴에서 짝수 번 교대한다. 위아래 흔들림은 0칸에서 2칸 범위의 코사인 곡선이다. 프레임 간격은 1/24초다.
- AC-3: 서 있기는 점 자리까지 포함한 전체 가운데에 그려 배지가 없을 때도 좌우 여백이 거의 같다. 캔버스 크기는 상태와 배지 여부와 관계없이 같다.
- AC-4: 잠든 모습은 6프레임(간격 0.6초)이며, 몸이 1칸 내려앉고 눈은 한 줄만 남는다. z 모양과 위치가 프레임 표와 일치한다. 확인하지 않은 완료 점이 있으면 z 대신 점을 같은 자리에 그린다.
- AC-5: 폭죽은 24프레임이며 알갱이 14개의 위치, 크기(3, 2, 1), 투명도, 섬광(앞 20%)이 원본 식과 일치하고, 캐릭터 뒤에 합성된다. 마지막 프레임의 알갱이는 완전히 투명하다.
- AC-6: 배지는 승인 대기가 확인하지 않은 완료보다 우선하고 둘 다 없으면 그리지 않는다. 물음표는 5x7 격자의 호박색, 완료 점은 4x4 보라색이며 캐릭터 오른쪽 위(캐릭터 폭 24칸 + 간격 1칸)에 붙는다. 위아래 흔들림은 따라가지 않는다. 잠든 모습은 승인 대기 배지를 그리지 않는다(원본과 같다).
- AC-7: 색상 모드가 반영된다. 흰색은 몸이 흰색, 컬러는 `#DD8B70`이며 눈 색은 같다. 완료 점 색은 패널에서 쓰는 보라색과 같은 값이다.
- AC-8: 상태 선택이 원본과 같다. 달리는 세션이 있거나 폭죽이 재생 중이면 달리기 주기로 갱신하며, 폭죽이 재생 중이어도 달리는 세션이 없으면 서 있는 모습 위에 합성한다. 그렇지 않고 잠든 상태이면 잠든 프레임을, 아니면 서 있는 모습을 보여 준다. 폭죽은 마지막 프레임 뒤에 끝난다.
- AC-9: 이미지 묶음은 색상 모드와 배지가 같으면 다시 만들지 않고, 바뀌면 서 있기, 달리기, 잠듦 이미지를 모두 다시 만든다. 이미지는 비트맵 기반이며 템플릿 이미지가 아니다.
- AC-10: 원본의 24fps 판단 근거와 주기 상수의 의미가 `docs/reverse/menubar-icon.md`에 근거 위치와 함께 기록된다. 원본이 주장하는 CPU 수치를 검증하지 못하면 검증하지 못했다고 적는다.
- AC-11: `MenuBarIcon`이 `Boundaries`를 import하지 않고, 파일과 시간과 프로세스에 접근하지 않는다.
- AC-12: `apps/macos`에서 `swift build`와 `swift test`가 통과하고 결과가 기록된다. 미실행과 실패를 성공으로 보고하지 않는다.
- AC-13: 모든 상태의 이미지를 한 장의 시트로 내려 육안으로 원본과 대조한 결과가 기록된다. 실제 메뉴바에 올려 보는 확인과 CPU 사용 비교는 앱이 조립되는 #11에서 하며, 이 이슈에서는 미검증으로 남긴다.

## 미결정 사항

없음. 구현을 막는 항목은 없다.

원본의 특이점(폭죽 프레임 비캐시, 생성 시점의 화면 배율 고정, 보정 색을 `DeviceRGB`에 그리는 방식, 물음표 색 차이)은
모두 원본 동작을 유지하며, 근거는 [원본 동작 문서](../../reverse/menubar-icon.md)에 기록한다.
동작을 바꾸려면 별도로 결정한다. 폭죽과 CPU의 실측 비교는 #11에서 한다.

- specRevision: 1

- 구현 상태: 같은 내용이 로컬 실험 워크트리(`feat/mouse-gaze/test`)에서 커밋 없이 완성되어 있고, 이 브랜치로 옮겨 정리하는 작업이다. 우주선 게임은 만들었다가 지워서 포함하지 않는다.

## 목적

캐릭터를 바탕으로 한 가벼운 아케이드 요소로, 앱을 소개하고 재미를 주는 셔틀콕 미니게임을 만든다.

- 메뉴바 캐릭터는 그 자리에 두고, 게임만 화면 위에 나타난다.
- 시작과 종료가 쉽다. 우클릭 메뉴로 시작하고 ESC로 즉시 끝낸다.
- 다른 앱의 아이콘을 옮기거나 시스템 설정을 바꾸지 않고, 게임 중에만 메뉴바 오른쪽을 비운다.
- 규칙은 시간, 난수, 마우스를 밖에서 받는 순수한 구조체로 만들어 같은 입력이면 같은 결과가 나오게 한다.

## 작업 범위

### 포함

- 설정 메뉴(우클릭) 맨 위에 "셔틀콕 게임 (ESC로 종료)" 항목
- 화면 전체를 덮는 투명 오버레이 창(마우스는 아래 앱으로 통과, 키 입력은 받음)
- ESC로 즉시 종료(키 이벤트와 키 상태 확인을 함께 사용해 포커스를 잃어도 끌 수 있음), 게임이 끝난 뒤 Space나 Return으로 다시 시작
- 게임 시작 때 메뉴바 맨 오른쪽에 빈 아이콘을 만들고 폭을 늘려 다른 아이콘을 왼쪽으로 쓸어내기, 끝나면 빈 아이콘을 지워 원래대로 복구
- 빈 아이콘이 제자리를 잡은 것을 확인한 뒤에 비울 폭을 정하기(제한 시간 3초)
- 셔틀콕 랠리 규칙(`RallyGame`)
  - 쉬운 규칙: 라켓(마우스)에 닿기만 하면 점수 +1이고 셔틀콕이 캐릭터 쪽으로 돌아간다. 맞은 위치로만 방향이 정해지고 스윙 속도는 보지 않는다. 목숨은 1개다.
  - 캐릭터는 메뉴바에서 셔틀콕을 따라 좌우로 달린다.
  - 점수가 오를수록 셔틀콕과 캐릭터가 빨라진다(점수 30에서 최대 1.8배).
  - 점수는 메뉴바 캐릭터 옆 숫자로만 표시하고, 최고 기록은 `UserDefaults`에 저장한다.
  - 끝나면 캐릭터 아래에 "SPACE 다시  ESC 끝"만 보여 준다.
- 셔틀콕 그림(형광 연두 깃털, 형광 분홍 코르크, 형광 빛 번짐)
- 게임 중 메뉴바 캐릭터는 같은 폭의 빈 이미지로 바꾸고(`setGameMode`), 쉬는 동작과 시선 타이머도 멈춘 뒤 끝나면 현재 상태대로 되돌림
- 공통 바탕 분리: 창, ESC, 아이콘 비우기는 `GameHost`, 게임별 화면은 `GameScene` 프로토콜과 `RallyScene`
- 규칙 단위 테스트, `docs/architecture.md`의 `MiniGame` 행 추가

### 제외

- 우주선 게임과 그 밖의 다른 게임(만들었다가 지웠다)
- 점수 공유, 점수판 서버, 소리, 설정 화면에서 게임 켜고 끄기
- 캐릭터 시선과 쉬는 동작 변경(#61에서 병합됨)
- README와 랜딩 페이지 설명
- 명세 선행 커밋 이외의 요청되지 않은 커밋, push, PR과 merge

## 설계 결정

- 파일 구조와 로직의 책임:
  - `MiniGame`(순수 모듈): `RallyGame`(규칙), `RallyArt`(셔틀콕 그림). AppKit 창과 타이머를 모른다.
  - `Desktoto`: `GameHost`(오버레이 창, ESC, 60Hz 타이머, 아이콘 비우기 진행, 다시 시작), `GameScene`(장면 프로토콜과 문구 설정), `RallyScene`(셔틀콕 장면의 레이어), `MenuBarClearer`(빈 아이콘으로 메뉴바 비우기), `AppDelegate`(메뉴 항목과 시작), `MenuBarIconController`(게임 중 캐릭터 숨김)
- 상태와 데이터 흐름:
  - 호스트가 시작하면 오버레이를 띄우고 `MenuBarClearer`가 빈 아이콘을 만든다. 아이콘이 오른쪽 영역에 놓이면(최대 3초 대기) 비울 폭을 정하고 0.5초 동안 폭을 늘린다. 다 비워지면 `scene.begin`을 부른다.
  - 매 프레임 호스트가 마우스 위치와 시간(최대 1/20초로 제한)을 장면에 넘기고, 장면이 규칙을 진행해 레이어 위치를 갱신한다.
  - 종료하면 장면 레이어를 치우고 빈 아이콘을 지우며(`end`), `onFinish`로 컨트롤러가 캐릭터를 되돌린다.
- 선택한 방식과 이유:
  - 아이콘을 쓸어내는 일은 불투명 띠를 얹지 않고 맨 오른쪽에 빈 아이콘을 만들어 폭을 늘리는 방식으로 한다. 시스템이 실제로 아이콘을 왼쪽으로 밀어내며, 다른 앱의 아이콘이나 시스템 설정을 건드리지 않고, 빈 아이콘을 지우면 모두 돌아온다.
  - 빈 아이콘은 위치 설정 키(`NSStatusItem Preferred Position DesktotoGameSpacer`)를 20으로 두고 만든다. 시작할 때만 읽히므로 만들기 전에 정하고, 끝나면 키를 지운다.
  - 라켓에 닿기만 해도 돌려보내는 쉬운 규칙과 목숨 1개는 사용자가 정했다(스윙 속도 반영은 어렵다는 이유로 뺐다).
  - 규칙은 시간 간격과 난수를 인자로 받아 테스트한다.
- 예외 처리:
  - 화면이나 상태 막대 창을 찾지 못하면 게임을 시작하지 않는다.
  - 빈 아이콘이 3초 안에 제자리를 잡지 못해도 있는 그대로 진행한다(게임이 멈추지 않는다).
  - 이미 게임이 실행 중이면 다시 시작하지 않는다.
  - 프레임 간격이 매우 커도(1/20초로 제한) 셔틀콕이 순간이동하지 않는다.
  - 강제로 종료해 남은 빈 아이콘 위치 설정 키는 다음 게임 시작 때 다시 덮어쓴다.

## 완료 조건

- AC-1: 우클릭 설정 메뉴 맨 위에 "셔틀콕 게임 (ESC로 종료)"가 있고, 누르면 게임이 시작된다.
- AC-2: 게임 중에는 화면 위에 셔틀콕과 라켓(마우스 위치)이 보이고, 마우스 클릭은 아래 앱으로 전달된다.
- AC-3: ESC를 누르면 즉시 끝나고, 끝나면 메뉴바 아이콘이 원래대로 돌아온다. 끝난 뒤 Space나 Return으로 다시 시작한다.
- AC-4: 시작할 때 메뉴바 오른쪽의 다른 아이콘이 실제로 왼쪽으로 쓸려 나가고(최대 폭 520pt), 끝나면 모두 돌아온다. 빈 아이콘이 늦게 놓여도 게임이 시작된다.
- AC-5: 게임 중 메뉴바 캐릭터는 같은 모양의 캐릭터가 셔틀콕을 따라 좌우로 달리고, 점수 숫자가 그 옆에 보인다. 실제 메뉴바 캐릭터와 쉬는 동작 타이머는 멈춘다.
- AC-6: 라켓에 닿으면 점수가 1 오르고 셔틀콕이 캐릭터가 달려 닿을 수 있는 곳으로 돌아간다. 맞은 위치가 셔틀콕이 가는 방향을 정한다.
- AC-7: 놓치면 끝난다(목숨 1개). 끝나면 캐릭터 아래에 "SPACE 다시  ESC 끝"이 보이고 최고 기록이 저장된다.
- AC-8: 점수가 오를수록 셔틀콕이 빨라지고 점수 30에서 최대 1.8배에서 멈춘다.
- AC-9: 같은 입력이면 같은 결과가 나온다(시간, 난수, 마우스를 밖에서 받는다).
- AC-10: `docs/architecture.md`에 `MiniGame` 행이 있다.
- AC-11: `swift build`와 `swift test`가 통과한다.

## 미결정 사항

- 게임을 다른 화면(외장 모니터, 노치 없는 화면)에서 시작했을 때의 아이콘 비우기는 확인하지 못했다. 구현을 막지 않는다.
- 우클릭 메뉴로 시작하는 경로에서 빈 아이콘이 제자리를 늦게 잡는 문제를 대기 확인으로 막았는데, 실제로 사라졌는지는 확인하지 못했다(원인은 가설이다).
- 강제 종료 시 남는 위치 설정 키가 다른 문제를 일으키는지는 확인하지 못했다.

네트워크나 실제 사용자 설정을 사용하는 동등성 검증의 통과를 의미하지 않는다.

## 최종 검토

- 범위: 현재 브랜치의 커밋, 병합 내용, 미커밋 수정과 새 파일 전체. 구현, 가짜 경계, 테스트, 리소스, 패키지 등록과 문서를 확인했다.
- 설정 보존: 다른 hook과 사용자 필드를 유지하고, 복원할 수 없는 외부 wrapper는 전체 설정을 바꾸지 않고 실패로 반환한다.
- 파일 실패: 파일 없음과 읽기 실패를 구별한다. 백업 실패 시 설정 저장을 하지 않으며, 심볼릭 링크의 실제 대상에 백업과 원자적 쓰기를 수행한다.
- 수명과 중복: 서비스 actor의 동기 구간에서 연결과 해제를 직렬화하며, 반복 연결 시 파일을 쓰지 않는다.
- 모듈 영향: #6의 사용량 구현과 프로세스 경계를 변경하지 않았다. 두 테스트 타깃 등록과 경계 문서를 함께 유지했다.
- 검증 보강: ScriptTests.swift의 statusLine 실행을 리소스 직접 호출에서 Live 서비스가 설치한 경로의 생성 명령 실행으로 보강했다. 이후 전체 테스트를 다시 실행했다.
- 검토한 범위에서 미해결 High와 Medium 지적은 발견하지 않았다. 실제 Claude Code 인증과 이벤트 호환성은 검증 제한으로 남아 있다.

사용자는 인증 진행 대신 실제 연동을 미검증으로 기록하도록 선택했다. 이 선택에 따라 인증된 CLI 실행은 추가로 진행하지 않았다.

## 남은 항목

- 인증된 임시 Claude Code에서 Notification(permission_prompt)과 statusLine 호출, 기존 표시와 해제 후 복원을 확인해야 한다.
- 원본 앱과 새 앱의 실제 표시 동등성은 앱 조립 후 비교해야 한다.
- 최초 자동 연결 기본값과 영속 설정 저장은 #11과 함께 확정해야 한다.
- 설치 후 백업이나 설정 쓰기가 실패하면 스크립트가 남을 수 있다. 외부 편집기와 여러 앱 프로세스 사이의 완전한 트랜잭션은 제공하지 않는다.
- 이 기록은 PR 게시 승인이 아니며, 실제 연동 미검증 상태를 성공으로 표시하거나 #7 전체 완료로 선언하지 않는다.

## CodeRabbit 지적 수정 검증

- 2026-11-03: PR #19의 입력 보존 지적 2개를 사용자 승인 후 수정했다. 문서 주석 커버리지 경고는 이번 수정 범위에 포함하지 않는다.
- 먼저 회귀 테스트를 추가해 기존 스크립트에서 실패를 확인했다. hook의 transcript 우선과 session_id 대체 두 경로에서 JSON 이스케이프 때문에 대기 파일을 만들지 못했고, statusLine은 LF 한 개와 두 개, CRLF 입력의 저장과 전달에서 실패했다.
- 수정 후 전체 테스트 181개와 셸 문법 검사가 통과했다. ClaudeIntegrationTests는 30개이며 ScriptTests 4개 안에서 매개변수 입력을 추가로 실행한다.
- 릴리스 앱 번들 빌드와 서명 검증을 다시 통과했고 번들의 두 스크립트가 수정된 저장소 리소스와 일치함을 확인했다. 원본 스크립트와의 바이트 일치는 더 이상 요구하지 않는다. 승인된 입력 손실 보정 2개만 원본과 다르다.
- 실제 Claude Code 이벤트와 원본 앱의 동등성은 계속 미검증이다. 실제 사용자 설정과 원본 소스는 변경하지 않았다.

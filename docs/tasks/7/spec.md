# 작업 명세: [Feat] Claude Code 연동 구현

## 연결 정보

- 이슈: #7 / https://github.com/huniversal/Desktoto/issues/7
- 브랜치: `feat/claude-integration/#7`
- specRevision: 2
- 대상 ai-run 원본:
  - `~/Desktop/ai-run/Sources/AiRun/ClaudeIntegration.swift`
  - `~/Desktop/ai-run/scripts/ai-run-hook.sh`
  - `~/Desktop/ai-run/scripts/ai-run-statusline.sh`
  - `~/Desktop/ai-run/Sources/AiRun/AppDelegate.swift`의 연동 시작과 메뉴 처리
- 동작 문서화 위치: `docs/reverse/claude-integration.md`

## 목적

Claude Code의 승인 대기와 사용량 입력을 앱에 전달하는 연동을 연결하고 해제한다.
사용자의 기존 설정과 statusLine 명령을 보존하고, 사용자 설정에 접근하는 동작을 임시 경로에서 검증할 수 있게 한다.

## 작업 범위

### 포함

- Notification의 permission_prompt hook 추가와 제거, 다른 hook과 설정 보존
- 기존 command statusLine을 감싸 실행하고 해제 시 원래 명령으로 복원
- 연결 상태 조회, 반복 연결과 해제의 무변경 처리
- 기존 설정 백업, 원자적 저장, 읽기 불가와 손상된 JSON 보호
- 두 스크립트의 리소스 이식과 설치 경로 주입
- 사용자 해제 후 시작 시 재연결을 건너뛰는 정책의 테스트 가능한 입력과 판정
- 순수 변환, 셸 인용, 파일 실패 경로와 스크립트의 합성 입력 테스트

### 제외

- 사용량 JSON 읽기와 사용량 계산 (#6)
- 실제 앱 시작, 메뉴와 영속 설정 조립 (#11)
- 사용자의 실제 `~/.claude`, `~/.ai-run`, 설치된 앱 변경
- 원본 소스 변경, 앱 설치, 배포, CI 변경
- 명세 선행 커밋 이외의 요청되지 않은 커밋, push, PR과 merge

## 설계 결정

- 파일 구조와 책임: `apps/macos/Sources/ClaudeIntegration/`에서 순수 설정 변환과 파일 연동 서비스를 분리한다. 파일별 세부 이름은 구현 시 역할에 맞춰 정한다.
- 경계: `apps/macos/Sources/Boundaries/`에 설정 파일 읽기와 쓰기에 필요한 별도 프로토콜과 Live 구현을 추가한다. 기존 읽기용 `FileSystem`, 프로세스 경계와 #6 구현은 변경하지 않는다. 가짜 구현은 `apps/macos/Sources/TestSupport/`에 추가한다.
- 리소스: `apps/macos/Resources/ai-run-hook.sh`, `apps/macos/Resources/ai-run-statusline.sh`를 번들의 Resources에 포함한다. 기존 `apps/macos/scripts/build-app.sh`의 RESOURCES_DIR 지원을 활용하고 기본 리소스 경로 처리 필요 여부를 확인한다.
- 테스트 등록: `apps/macos/Package.swift`에 ClaudeIntegrationTests를 추가한다. 변경 시 `docs/architecture.md`도 맞춘다.
- 상태: 연결 상태는 설정 파일에서 조회한다. 사용자의 자동 연결 허용 여부는 호출자가 전달하며, 영속 저장 책임은 #11에 둔다. 해제 이후 허용 여부가 false이면 시작 연결은 파일을 변경하지 않는다.
- 호환성: #2에서 결정한 `~/.ai-run`, 두 스크립트 이름, waiting 파일과 status JSON 형식을 유지한다. #6과의 직접 import는 추가하지 않는다.
- 순수 변환: hook 추가와 제거, statusLine 연결과 복원, 셸 인용은 파일 시스템 없이 검증한다. 사용자 명령은 설정 분석 중 실행하지 않는다.
- 보존: 다른 설정과 hook, statusLine의 추가 필드를 보존한다. 이미 status 저장 기능이 있는 사용자 스크립트는 원본처럼 중복으로 감싸지 않는다. 사용자 스크립트 검사는 최대 65,536바이트로 제한한다.
- 안전한 쓰기: 설정 파일의 심볼릭 링크를 해석한 실제 대상에 백업과 원자적 쓰기를 수행한다. 기존 설정은 읽기에 성공한 경우에만 변경한다. 백업 실패 시 설정 쓰기를 진행하지 않는다. 같은 초의 백업은 번호를 붙여 보존한다.
- 실패 처리: 설정 없음과 읽기 실패를 구별한다. 빈 파일은 원본처럼 빈 객체로 취급하고, 객체가 아닌 JSON과 손상된 JSON은 실패로 보고 원본을 보존한다. 스크립트 설치나 설정 쓰기 실패를 연결 성공으로 보고하지 않는다. 설치 후 설정 쓰기가 실패하면 스크립트가 남을 수 있으며 그 한계를 결과와 검증에 기록한다.
- 재진입: 같은 서비스 인스턴스의 연결과 해제는 직렬화한다. 외부 편집기와 여러 앱 프로세스에 걸친 완전한 트랜잭션은 보장하지 않는다.

- 승인된 해제 방식: 외부 명령으로 감싼 statusLine은 설정 전체를 변경하지 않고 복원 불가를 반환한다. 정확히 생성한 형식만 복원한다.

## 완료 조건

- AC-1: Notification permission_prompt hook을 중복 없이 추가하고 앱 hook만 제거한다. 다른 이벤트, 같은 그룹의 다른 hook과 사용자 필드는 유지한다.
- AC-2: statusLine이 없으면 앱 명령을 추가한다. command 형식이면 기존 명령을 동일 입력으로 실행하도록 감싸고, 연결 후 해제하면 기존 command와 추가 필드를 복원한다. 다른 형식은 덮어쓰지 않는다.
- AC-3: 공백, 작은따옴표, 큰따옴표, 역슬래시, 달러 기호와 개행을 포함한 명령을 셸 인용한 뒤 정확히 복원한다. 설정 조회만으로 명령이 실행되지 않는다.
- AC-4: 원본에서 이미 연결한 설정과 status 저장 기능이 있는 사용자 스크립트를 인식한다. 완전 연결 상태에서 다시 연결할 때 설정과 스크립트를 쓰지 않는다. hook만 있거나 statusLine만 있는 상태도 구별한다.
- AC-5: 설정 변경 전에 원본 바이트를 백업하고 같은 초의 백업도 덮어쓰지 않는다. 임시 파일 후 교체로 저장하며 심볼릭 링크는 유지하고 실제 대상을 변경한다.
- AC-6: 읽기 불가, 손상된 JSON, JSON 객체가 아닌 파일은 변경하지 않는다. 백업 실패 시 설정 변경을 하지 않고, 스크립트 설치와 설정 쓰기 실패를 명시적으로 반환한다.
- AC-7: 두 스크립트가 리소스에 포함되고 주입된 설치 경로로 복사된다. 공백과 작은따옴표가 있는 경로도 올바른 셸 명령으로 연결한다.
- AC-8: hook은 transcript_path의 파일 이름을 우선하고 없으면 session_id를 사용해 waiting 파일에 초 단위 시각을 쓴다. statusLine은 입력 JSON을 status/<session_id>.json에 임시 파일 후 교체로 보존하고, 기존 명령에 같은 표준 입력을 전달해 출력을 유지한다.
- AC-9: 자동 연결 허용이 false이면 시작 연결은 설정과 스크립트를 변경하지 않는다. 명시적 연결과 해제는 별도 동작으로 제공한다. 최초 실행 기본값은 미결정 사항으로 남긴다.
- AC-10: 순수 로직과 실패 주입 테스트는 실제 사용자 경로를 읽거나 쓰지 않는다. Live 파일 쓰기와 스크립트 테스트도 임시 폴더와 임시 HOME만 사용한다.
- AC-11: `swift build`, `swift test`와 리소스를 포함한 앱 번들 빌드 결과를 기록한다. 미실행과 실패를 성공으로 보고하지 않는다.
- AC-12: 원본과의 실제 Mac 연동 동등성은 별도 검증 결과로 기록한다. 합성 테스트와 빌드 성공만으로 실제 Claude Code 연동 완료를 선언하지 않는다.

## 미결정 사항

- 최초 실행의 자동 연결 기본값은 #7과 #11에서 확정해야 한다. 제안은 미설정 상태에서는 자동 연결하지 않고 명시적 연결을 받는 방식이다. #7 모듈의 명시적 연결과 비허용 시 건너뛰기 구현을 막지 않는다.
- 없음. 외부 명령으로 감싼 statusLine은 변경하지 않고 복원 불가를 알리는 처리에 사용자 승인을 받았다. 정확한 생성 형식만 복원한다.
- 저장 시 실패한 스크립트 설치의 전역 롤백은 원본에 없다. 현재 설계는 설정 파일 보존과 실패 결과에 집중하며, 설치된 스크립트가 남는 경우를 명시한다.
- 명세 선행 커밋과 구현 진행에 사용자 승인을 받았다. push와 PR 권한은 포함하지 않는다.

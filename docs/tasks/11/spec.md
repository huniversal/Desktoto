## 목적

#4부터 #10에서 따로 만든 모듈을 `Desktoto` 실행 파일에서 하나의 메뉴바 앱으로 조립하고,
원본 `ai-run`과 제품 동작이 같은지 나란히 실행해 검증한다.
현재 `apps/macos/Sources/Desktoto/main.swift`는 주석 한 줄뿐이라, 이 이슈가 끝나야 앱이 실제로 실행된다.
조립 계층에서 새로 정하는 것은 내부 구조뿐이고, 제품 동작(주기, 문구, 소리, 순서)은 원본과 같게 유지한다.

## 작업 범위

### 포함

- 앱 진입점: `NSApplication` 시작, 메뉴바 전용(accessory) 정책, `NSStatusItem` 생성
- 감시 타이머와 상태 전달
  - 1초 폴링: 세션 상태, 승인 대기 종류 조회 후 완료와 대기 전이 판정
  - 패널이 닫혀 있는 동안 사용량 사전 읽기(30초), Codex 실시간 조회 요청(300초)
  - 패널이 열려 있는 동안 2초마다 패널 값 갱신, Codex 실시간 조회 요청(30초)
  - 감시 결과를 `SessionPanelModel`과 `IconImageSet`으로 전달
- 세션 정렬: 승인 대기, 진행 중, 방금 끝남, 나머지 순서이고 같은 순위 안에서는 감시기가 준 순서를 유지 (#10에서 #11로 이월)
- 패널 열기와 닫기: 0.15초 페이드, 바깥 클릭으로 닫기, Esc로 닫기, 상태바 아이콘 위치에 맞춘 창 배치, 두 패널을 모두 끈 경우 열지 않음 (#10에서 이월)
- 설정과 모델의 동기화: `AppSettings`의 표시 설정을 `SessionPanelModel`로 전달, `Theme`을 패널 창 외관으로 적용 (#10에서 이월)
- 메뉴바 아이콘 상태: 확인하지 않은 완료 점, 승인 대기 표시, 달리기 애니메이션, 완료 폭죽, 잠듦(마지막 활동 후 600초), 색상 변경 시 이미지 재생성 (#9에서 이월)
- 알림 트리거와 소리
  - 완료: 소리(Glass) 1회, 세션마다 알림 "작업이 끝났어요"
  - 대기: 소리(Ping) 1회, 세션마다 알림 "답변이 필요해요" 또는 "승인이 필요해요"
  - 알림 제목은 40자로 자르고, 알림 설정이 꺼져 있으면 배너만 생략 (#8에서 이월)
- 세션 열기 연결: 줄 클릭과 알림 클릭 모두 패널을 닫고 `SessionOpener`로 연다 (메인 스레드에서 호출)
- 우클릭 설정 메뉴: `SettingsMenu.makeEntries`의 항목을 `NSMenu`로 조립하고 `SettingsAction`을 각 모듈 호출에 연결 (#8에서 이월)
- 시작 시 Claude Code 연동 자동 적용과 종료 시 정리 (`UsageMonitor.stop`)
- 앱 번들 패키징 확인: `build-app.sh`로 만든 `Desktoto.app`이 실행되는지
- 동등성 검증: ai-run과 새 앱을 나란히 실행해 기능 체크리스트로 대조하고, 일치, 의도한 차이, 원본 버그라서 고치지 않은 항목으로 분류해 문서로 남긴다
- 이전 이슈에서 이월된 실기기 확인: 메뉴바 실표시와 달리기 CPU 비교(#9), 알림 배너, 알림 클릭, 로그인 항목(#8), 패널 화면 대조(#10), 터미널 탭 이동(#5), 실제 기록 파일 대조(#4), 수집 계층 확인(#6), 승인 대기 표시(#7)
- README 갱신: 설치, 빌드, 구조

## 설계 결정

아래 중 "제안"으로 표시한 항목은 아직 사용자와 합의하지 않았다. 합의되면 이 표시를 지우고 specRevision에 반영한다. specRevision 2에서 D-1, D-2, D-3을 기본안으로 확정했다.

- 파일 구조와 로직의 책임
  - `Desktoto` 실행 파일 안에서 AppKit과 타이머를 만지는 계층과, 판정만 하는 순수 값 타입을 나눈다. 순수 로직은 `Desktoto` 실행 파일 안에 두고 `DesktotoTests`가 `@testable import Desktoto`로 검증한다 (D-3 확정).
  - 순수 로직 후보: 폴링 틱의 전이 판정(완료, 새로 대기 중), 패널 세션 정렬, 알림 제목 자르기와 문구 선택, 잠듦 판정, 갱신 주기 선택.
    원본은 이 로직이 `AppDelegate` 한 클래스에 섞여 있어 테스트가 불가능했다.
  - AppKit 계층 후보: 앱 진입점, 상태바 항목과 설정 메뉴 조립, 패널 열기와 닫기와 바깥 클릭, 타이머 실행, 소리 재생.
  - 모듈 의존은 `docs/architecture.md` 3장을 따른다. 기능 모듈끼리 import하지 않고 조립은 `Desktoto`만 한다. 모듈 경계 밖의 새 공용 계층은 만들지 않는다.
- 상태와 데이터 흐름
  - 감시 결과(세션 상태, 대기 종류, 사용량)는 actor인 `SessionMonitor`, `UsageMonitor`에서 `await`로 받아 메인 액터의 `SessionPanelModel`과 아이콘 상태에 넣는다.
  - 메뉴바 아이콘 상태와 패널 모델은 메인 액터가 단일 소유자다. 폴링 결과가 늦게 도착해도 이전 결과가 새 상태를 덮어쓰지 않게 틱 순서를 보장한다 (이전 틱이 끝나기 전에는 다음 틱을 시작하지 않거나, 오래된 결과를 버린다. 방식은 구현 때 정하고 PR에 적는다).
  - 설정 변경은 `AppSettings`가 단일 출처이고, 모델과 창 외관, 아이콘은 변경 시점에 한 방향으로 반영한다.
- 선택한 방식과 이유
  - 타이머는 원본과 같은 주기를 유지한다 (1초, 2초, 사용량 사전 읽기 30초, Codex 열림 30초와 닫힘 300초, 잠듦 600초). 동작을 같게 두는 것이 이 이슈의 목적이다.
  - 잠듦 시간 환경 변수 `AIRUN_SLEEP_AFTER`는 원본 확인용 기능이다. 새 앱에도 같은 이름으로 유지할지 정하는 일은 미결정 D-2에 있다.
  - 동등성 검증에서 새 앱과 원본은 같은 `~/.ai-run`과 `~/.claude` 입력을 읽는다 (아키텍처 문서의 결정). 원본과 새 앱이 동시에 떠 있으면 같은 이벤트에 알림이 두 번 나온다. 이것은 병행 실행의 한계이지 새 앱의 결함이 아니므로 검증 문서에 적는다.
- 예외 처리
  - 설정 파일을 읽을 수 없거나 형식 오류인 경우 연동은 건드리지 않고 로그만 남긴다 (`ClaudeIntegration.Result.failed`). 앱 시작은 막지 않는다.
  - 알림 권한 거부, 세션 열기 실패(`SessionOpener.open`이 false), Codex 조회 실패는 앱 동작을 멈추지 않고 이전 표시를 유지한다. 각 경우의 사용자 표시는 원본과 같게 한다.
  - 번들 없이 `swift run`으로 실행하면 정식 알림 대신 AppleScript 알림을 쓰고, 로그인 항목 메뉴는 비활성이다 (`AppBundle.isRunningAsApp`).

## 완료 조건

- AC-1: `swift build`와 `swift test`가 통과하고, CI의 `macOS Build`와 `CI Result`가 통과한다.
- AC-2: `build-app.sh`로 만든 `apps/macos/build/Desktoto.app`을 열면 메뉴바에 캐릭터 아이콘이 나타나고 Dock에는 나타나지 않는다.
- AC-3: 상태바 아이콘 좌클릭으로 패널이 열리고 닫힌다. 바깥 클릭과 Esc로도 닫히며, 열림과 닫힘에 0.15초 페이드가 적용된다. 두 패널 표시를 모두 끄면 열리지 않는다. 우클릭은 설정 메뉴를 연다.
- AC-4: 패널 세션 목록이 승인 대기, 진행 중, 방금 끝남, 나머지 순서로 정렬되고 같은 순위는 감시기 순서를 유지한다. 합성 입력 단위 테스트로 확인한다.
- AC-5: 진행 중이던 세션이 `completed`가 되면 완료로 판정한다. 질문 대기 중인 세션과 시간이 지나 만료된 세션은 완료로 보지 않는다. 같은 대기 세션에 알림이 반복되지 않는다. 합성 입력 단위 테스트로 확인한다.
- AC-6: 완료 시 Glass 소리 1회, 세션마다 "작업이 끝났어요" 알림. 대기 시 Ping 소리 1회, 세션마다 질문이면 "답변이 필요해요", 아니면 "승인이 필요해요". 제목은 40자를 넘으면 잘라 말줄임표를 붙이고, 세션 제목이 없으면 프로젝트 이름, 둘 다 없으면 "AI"를 쓴다. 알림 설정이 꺼져 있으면 배너만 생략하고 소리와 아이콘 표시는 유지한다. 문구와 선택 규칙은 단위 테스트로, 소리와 배너는 실기기로 확인한다.
- AC-7: 아이콘이 상태에 맞게 바뀐다. 확인하지 않은 완료 점(패널을 여는 순간 지워짐), 승인 대기 표시, 달리기 애니메이션, 완료 폭죽, 마지막 활동 후 600초가 지나면 잠든 모습. 상태를 고르는 규칙은 단위 테스트로, 실제 표시는 실기기로 확인한다.
- AC-8: 패널 줄 클릭과 알림 클릭이 모두 패널을 닫고 그 세션을 연다. 데스크탑 앱 대화는 링크로, 터미널 세션은 해당 터미널 탭으로 이동한다.
- AC-9: 갱신 주기가 원본과 같다. 패널 닫힘 동안 사용량 사전 읽기 30초와 Codex 요청 300초, 열림 동안 패널 갱신 2초와 Codex 요청 30초. 주기 선택 규칙은 단위 테스트로 확인한다.
- AC-10: 설정 메뉴의 모든 항목(`SettingsAction` 10종)이 동작한다. 색상과 테마와 Liquid Glass 단계와 표시할 패널이 즉시 반영되고 재시작 후 유지된다. 로그인 항목은 앱 번들 실행에서만 활성이다. 종료 항목은 앱을 끝낸다.
- AC-11: 최초 실행(허용 여부 미설정)에서는 Claude Code 연동을 자동으로 넣지 않고 설정 파일을 조회하거나 바꾸지 않는다. 메뉴의 "Claude 연동"을 눌러 명시적으로 켠 뒤에만 연결하고, 켠 상태에서는 앱 시작 때 미연결이면 연결한다. 이미 연결됐으면 설정 파일을 바꾸지 않는다. 해제한 뒤에는 다시 넣지 않는다. 허용 여부는 `UserDefaults`에 저장한다. 앱 종료 시 Codex 실시간 조회를 멈춘다. 미설정과 해제를 구분해야 하므로 `AppSettings.connectsClaudeCode`의 미설정 기본값(현재 true)을 바꾸거나 별도 상태로 구분하며, 이때 `PreferencesTests`를 함께 고친다.
- AC-12: ai-run과 새 앱을 나란히 실행해 기능 체크리스트로 대조한 결과가 `docs/tasks/11/verification.md`에 기록된다. 각 항목은 일치, 의도한 차이, 원본 버그로 보고 고치지 않은 항목 중 하나로 분류되고, 미검증 항목은 미검증으로 이유와 함께 남는다. macOS와 Xcode 버전, 대상 외부 앱과 버전을 적는다.
- AC-13: 이전 이슈에서 이월된 실기기 확인(위 포함 범위 마지막 항목)의 결과가 같은 문서에 기록되고, 각 선행 이슈 문서의 "#11로 이월" 표시와 대응된다.
- AC-14: `docs/reverse/app-assembly.md`에 조립 계층의 원본 동작(주기, 전이 판정, 정렬, 알림 규칙, 시작과 종료 순서)이 기록되고, 필요하면 `docs/architecture.md`와 `docs/design-system.md`의 "#11" 언급이 현재 상태로 갱신된다.
- AC-15: `README.md`에 설치, 빌드, 구조가 갱신된다. 설명한 명령이 실제로 실행되어 확인된다.

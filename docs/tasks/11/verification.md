# #11 앱 조립 동등성 검증

## 환경과 방법

- 수행일: 2026-11-03, 한국 시간.
- macOS 27.0.1, Xcode 27.1. 새 앱은 `apps/macos/scripts/build-app.sh`로 만든 `apps/macos/build/Desktoto.app`(0.0.1, 번들 식별자 `com.huniverse.desktoto`)이다.
- 원본은 `~/Applications/Desktoto.app`에 설치된 `ai-run` 앱(번들 식별자 `com.huniverse.airun`, 2026-11-02 21:08부터 실행 중)이다. 원본 소스는 읽기만 했고 설치된 앱은 열어서 보기만 했다. 원본의 설정은 바꾸지 않았다.
- 두 앱을 같은 Mac에서 동시에 실행해 나란히 비교했다. 같은 `~/.claude`, `~/.codex`, `~/.ai-run`을 읽는다.
- 컴퓨터 제어 도구는 이 두 앱을 설치된 앱으로 인식하지 못해서(`~/Applications`와 빌드 폴더의 메뉴바 전용 앱) 접근 권한을 받을 수 없었다. 대신 접근성(System Events)으로 프로세스 ID를 지정해 상태바 아이콘을 누르고 메뉴와 패널 텍스트를 읽었으며, 합성 마우스 이벤트로 우클릭과 줄 클릭을 했고, `screencapture`로 화면을 찍었다.
- 새 앱의 저장 설정은 비교 전에 원본 값(흰색, 보통 유리, 다크, 알림 켬)에 맞췄고, 끝난 뒤 원래 값(컬러, 틴트, 연동 끔)으로 되돌렸다.
- 사용량 값의 정답은 설치된 `codex`에 `account/rateLimits/read`를 직접 호출한 응답과 `~/.codex/sessions`의 최신 기록이다.

### 남은 시간이 멈춤 (원본 버그, 새 앱은 고친 상태로 유지)

같은 시각(02:41)에 두 앱 패널의 텍스트를 읽은 결과다. 서버 응답과 세션 기록 모두 Codex 5시간 창이 04:28에 초기화되고 주간 창이 11월 9일 23:28에 초기화된다고 한다.

| 항목 | 새 앱 | 원본 | 정답(서버 기준) |
| --- | --- | --- | --- |
| Claude 5시간 | 3시간 28분 | 3시간 32분 | 해당 없음(캐시 값) |
| Codex 5시간 | 1시간 47분 | 3시간 54분 | 1시간 47분 |
| Codex 주간 | 6일 20시간 | 6일 22시간 | 6일 20시간 |

원본의 Codex 값은 02:39에 찍은 화면과 같은 숫자였다. 시간이 지나도 줄어들지 않는다. 원본 `SessionPanelView.swift` 250행은 `resetsAt.timeIntervalSinceNow`를 화면을 그릴 때 한 번 계산하므로, 값이 바뀌지 않으면 다시 계산되지 않아 남은 시간이 멈춘다. 새 앱은 패널을 열 때와 열려 있는 동안 2초마다 `SessionPanelModel.now`를 갱신해서 남은 시간이 실제로 줄어든다. 새 앱은 02:39에 1시간 48분, 02:41에 1시간 47분이었고 이후 라이트 테마를 확인할 때는 1시간 43분으로 줄어 있었다.

이것이 사용량이 실시간으로 갱신되지 않는다고 느낀 증상과 같은 것으로 보인다. 수집 계층(Codex 실시간 조회와 Claude 데스크탑 캐시)은 두 앱에서 같은 값을 읽는다. 새 앱은 원본에 맞추지 않고 고친 상태로 유지하기로 사용자와 합의했다(명세 D-6, specRevision 3).

### 실제 이벤트 확인

컴퓨터 제어 도구가 앱을 인식하지 못해 사용자의 실제 `~/.claude`와 `~/.codex`를 쓰는 앱에서 이벤트를 직접 만들어야 했다. 앱은 `HOME` 환경 변수를 따르지 않아(Foundation이 계정 정보에서 홈을 읽는다) 가짜 홈 폴더 방식은 쓸 수 없었다.

- 완료: 임시 폴더에서 `claude -p`로 짧은 세션 하나를 실제로 실행했다(`한 단어로만 답해: 안녕`, haiku). 새 앱이 실행 중이던 세션의 완료를 감지해 아이콘에 점이 생겼고, 패널에 제목(첫 프롬프트)과 컨텍스트 4%와 방금 끝남 점이 나왔다. 패널을 열자 아이콘의 점이 사라졌고, 원본 아이콘은 열지 않아서 점이 남았다.
- 승인 대기: `~/.ai-run/waiting/<세션 id>`에 훅과 같은 형식(현재 시각 초)으로 신호 파일을 만들었다. 두 앱 아이콘에 물음표가 붙고 새 앱 패널에 "승인 필요" 알약이 맨 위에 나왔다. 확인 뒤 신호 파일은 지웠다.
- 남은 흔적: 테스트 세션 기록이 `~/.claude/projects/-private-tmp-...-evtcwd/`에 남아 있다(Claude Code가 만든 정상 기록). 10분이 지나면 패널 목록에서는 사라진다.

### 서브 에이전트와 Codex 제목 (의도한 차이, 사용자 요청)

패널에 서브 에이전트와 자동 리뷰 세션이 일반 세션처럼 올라오고, Codex 세션은 제목 없이 폴더 이름(Desktoto)만 나온다는 요청이다.

- Claude 서브 에이전트는 `<프로젝트>/<세션>/subagents/agent-*.jsonl`에 따로 기록된다. 이 Mac에서 Claude 서브 에이전트 폴더를 확인했다.
- Codex는 기록 첫 줄(`session_meta`)의 `source`로 구분된다. 일반 채팅은 문자열 `"vscode"`이고, 자동 리뷰는 `{"subagent": {"other": "guardian"}}`, 서브 에이전트는 `{"subagent": {"thread_spawn": ...}}`이다. 최근 기록 60개 중 52개(자동 리뷰 31개, 서브 에이전트 21개)가 서브 에이전트였다.
- Codex 스레드 제목은 `~/.codex/session_index.jsonl`에 `{id, thread_name, updated_at}` 줄로 쌓이고, 이름을 바꾸면 같은 id의 줄이 더 붙는다. 마지막 줄이 현재 이름이다. 최근 일반 채팅의 이름이 Codex 앱 사이드바의 `#6`, `#7`, `#8`, "서브 에이전트 세션 표시 확인"과 일치했다.
- 실제 기록 읽기 전용 확인: 기준 시각을 2026-11-03 00:31:48로 고정해 `SessionMonitor`를 실제 `~/.claude`와 `~/.codex`에 연결해 실행했다. 세션 8개(Claude 6개, Codex 2개)가 나왔고 서브 에이전트와 자동 리뷰 세션은 없었다. Codex 두 개의 제목은 "서브 에이전트 세션 표시 확인"과 "#7"이었다. 확인용 테스트는 실행 후 삭제했다.
- 합성 기록 단위 테스트 10개를 추가했다(`SubagentAndTitleTests.swift`).
- 원본과 다른 점이므로 판정과 알림의 대상에서도 서브 에이전트가 빠진다. 서브 에이전트가 승인을 기다려도 이 앱은 따로 알리지 않는다.
- 첫 줄을 아직 읽을 수 없는 방금 만든 Codex 기록은 일시적으로 일반 세션으로 보일 수 있고, 첫 줄이 읽히면 다음 갱신에서 빠진다.

### 연동 판정 (의도한 차이)

이 Mac의 `~/.claude/settings.json`은 훅을 개발 경로(`~/Desktop/ai-run/scripts/ai-run-hook.sh`)로 걸고 있다. 원본은 명령에 `ai-run-hook.sh`라는 이름이 들어 있기만 하면 연결된 것으로 본다(`ClaudeIntegration.hasHook`). 새 앱은 `~/.ai-run/bin`의 관리 경로로 만든 형태만 연결로 인정한다(#7에서 판정 강화). 그래서 같은 설정 파일에서 원본은 "Claude 연동" 체크, 새 앱은 체크 없음으로 나온다. 같은 이유로 연동 허용 설정이 켜진 새 앱을 실행하면 훅이 하나 더 추가될 수 있다. 아래 "사건 기록"이 그 결과다.

## 미검증 항목

실제 이벤트가 있거나 사용자 환경을 바꾸는 항목이라 이번에 실행하지 않았다. 해당 항목은 통과로 표시하지 않는다.

- 완료와 승인 대기 알림의 배너, 소리, 알림 클릭으로 세션 열기. 완료와 승인 대기 상황은 만들었지만 배너는 화면에 나타나지 않았다. 두 앱 모두 알림 설정(`com.apple.ncprefs`)에서 항목을 읽을 수 없어 권한 상태를 확정하지 못했고, 소리는 들을 수 없었다. 시스템 설정의 알림에서 앱 권한을 확인해야 한다.
- 완료 폭죽과 잠듦 표시. 폭죽은 순간 모습이라 캡처로 잡지 못했고, 잠듦은 지금 이 앱이 쓰는 세션이 진행 중이라 재현할 수 없었다. 규칙은 단위 테스트로만 확인했다.
- 터미널(iTerm2, Terminal, Orca) 탭 이동. 해당 터미널의 실제 세션이 필요하다.
- 로그인 항목 켜기와 끄기. 시스템 설정을 바꾼다.
- "Claude 연동" 켜기와 끄기. 사용자의 `settings.json`을 바꾼다.
- 달리기 CPU 비교. 같은 상태에서 새 앱 약 17퍼센트에서 24퍼센트, 원본 약 31퍼센트에서 32퍼센트가 한 번씩 측정됐지만 측정 조건을 통제하지 않은 참고값이다.
- 실제 앱 화면에서의 서브 에이전트 제외와 Codex 제목 표시. 현재 10분 안에 활동한 Codex 세션이 없어서 앱 화면으로는 보지 못했고, 같은 로직을 실제 기록에 읽기 전용으로 적용한 위 확인만 했다.
- 패널 열기와 닫기의 0.15초 페이드. 정지 화면으로는 확인할 수 없다.

## 사건 기록

스모크 테스트 중 처음 실행한 새 앱(02:30:59)이 `~/.claude/settings.json`에 `permission_prompt` 훅을 하나 추가하고 `~/.ai-run/bin` 스크립트 두 개를 덮어썼다. 이 앱의 저장 설정(`com.huniverse.desktoto`)에 이전 빌드가 남긴 `connectsClaudeCode = 1`이 있어서 새 기본값(꺼짐)이 적용되지 않았기 때문이다.

- `settings.json`은 사용자 승인 후 자동 백업(`settings.json.ai-run-backup-20261103-023059`)으로 되돌렸다. 되돌린 내용은 사용자가 미리 만들어 둔 `settings.json.before-desktoto-test`와 같다. 새 앱이 쓴 버전은 `settings.json.after-desktoto-smoke`로 보관했다.
- 새 앱 저장 설정의 `connectsClaudeCode`를 꺼서 다시 쓰지 않게 했다.
- `~/.ai-run/bin`의 스크립트 두 개는 덮어쓰기 전 내용을 보관하지 못해 되돌리지 않았다. 새 스크립트는 `echo`를 `printf`로 바꾼 정도의 차이다. 원본 앱이 다음에 시작할 때 자기 버전으로 다시 설치한다.
- 이후 모든 새 앱 실행은 연동 허용 설정이 꺼진 상태에서 했고, 실행 전후로 `settings.json`의 수정 시각과 내용이 그대로임을 확인했다.

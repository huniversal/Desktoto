## 목적

README 이미지는 2026-11-03에 만든 뒤 갱신하지 않았다. 그 사이 #75와 #77에서 토토의 모양과 상태 표현이 바뀌고 랜딩 페이지가 개편되어 README와 랜딩의 모습과 문구가 어긋난다.
README 이미지와 대체 텍스트를 현재 랜딩 페이지(`apps/web/index.html`)의 내용에 맞춘다.
README는 이미지로만 구성하는 기존 방침(#37)과 README 전용 구성(랜딩 화면을 그대로 쓰지 않음)을 유지한다.

## 현재 어긋난 부분

## 작업 범위

### 포함

- `docs/images/readme/source.html`: 히어로, 설치, 상태, 기능 슬라이드를 최신 랜딩 구성과 문구에 맞게 수정
  - 캐릭터 그리기를 바뀐 토토(만두 모양, 상태별 몸 색, 졸음은 납작한 몸)로 교체
  - "메뉴바" 표기를 앱과 같이 "상단바"로 통일
  - 상태 이름과 설명을 랜딩 문구로 교체
  - 기능 슬라이드를 벤토 구성으로 바꾸고 표시 패널 설정 설명을 추가
- 문제, 개인정보, 알림 슬라이드는 랜딩과 문구를 대조해 달라진 부분만 수정
- `docs/images/readme/*.png`: `docs/images/readme/build.sh`로 다시 캡처
- `README.md`: 바뀐 이미지의 대체 텍스트를 이미지 속 문구와 일치하게 수정

### 제외

- 랜딩 페이지(`apps/web`)와 앱 코드 변경
- 링크 미리보기 이미지(`apps/web/og-v2.png`) 교체
- README에 텍스트를 다시 넣는 것(이미지 전용 구성 유지)
- 다운로드 배지와 릴리스 에셋 변경
- 영어 README 추가

## 설계 결정

- 파일 구조와 로직의 책임
  - 이미지 원본은 기존처럼 `docs/images/readme/source.html` 한 파일이고, 슬라이드 하나가 PNG 한 장이다.
  - 캡처 스크립트 `docs/images/readme/build.sh`의 슬라이드 이름과 높이는 `source.html`의 CSS와 같아야 하므로, 슬라이드 높이를 바꾸면 둘을 함께 고친다.
- 상태와 데이터 흐름: N/A (정적 이미지와 문서 작업이라 런타임 상태가 없음)
- 선택한 방식과 이유
  - 문구의 기준은 `apps/web/index.html`이다. 랜딩과 README가 다시 어긋나지 않게 같은 문구를 옮긴다.
  - 이미지 전용 구성과 README 전용 레이아웃(#37)은 유지한다. 랜딩 화면을 캡처해서 쓰지 않는다.
- 예외 처리
  - 캡처에 필요한 Chrome이 없거나 웹 폰트를 받지 못하면 이미지가 다른 글꼴로 만들어질 수 있으므로, 만든 PNG를 직접 열어 확인한다.

## 미결정 사항

- 토토를 `source.html`에 그리는 방식. 앱 코드를 옮겨 직접 그릴지, 랜딩 페이지의 그리기 코드를 가져올지. 구현 전에 정하며, 구현을 막는다.
- 알림 이미지의 "Claude Code의 마스코트에서 영감을 받은 팬 작품" 문구를 유지할지. 랜딩은 바뀐 캐릭터를 쓰며 이 문구가 없다. 구현 전에 정하며, notice 슬라이드 수정을 막는다.
- 개인정보 이미지의 새 버전 확인 문구(IP 주소와 User-Agent 안내)를 유지할지, 랜딩처럼 줄일지. 코드의 실제 동작을 확인한 뒤 정한다.

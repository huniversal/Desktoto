## 연결 정보

- 이슈: #75 / https://github.com/huniversal/Desktoto/issues/75
- 브랜치: feat/notch-interaction/#75
- specRevision: 2
- 대상 ai-run 원본: N/A (#70에서 추가한 Desktoto 자체 기능)

## 목적

노치 봇이 사용자 동작과 세션 상태에 더 살아 있게 반응하게 한다.
표시 위치를 바꿀 때 랜딩 페이지 데모처럼 노치 봇과 메뉴바 토토가 물방울처럼 오가고,
펼친 노치는 주변 메뉴바 아이콘을 오래 가리지 않게 하며, 봇은 마우스와 세션 상태에 표정과 움직임으로 반응한다.

## 작업 범위

### 포함

1. 노치와 메뉴바 사이 물방울 전환
   - 우클릭 메뉴의 표시 위치에서 노치 ↔ 메뉴바를 바꿀 때 전환 애니메이션을 재생한다.
   - 노치 → 메뉴바: 봇이 노치에 붙은 채 끙끙대며 늘어나다 끊기고, 메뉴바 줄을 따라 통통 튀어 토토 자리에 앉는다.
   - 메뉴바 → 노치: 토토가 튀어 올라 노치 옆까지 오고, 노치에 닿아 싫어하듯 두 번 버티다가 흡수된다.
   - 노치 폭은 캐릭터 위치를 따라 줄고 는다(랜딩 데모와 같은 규칙).
   - 재생 시간은 떨어질 때와 붙을 때 모두 3초다.
   - 떨어질 때는 노치 안에서 맺힌 물방울이 부풀며 나와 눈물방울처럼 끊기고, 메뉴바에 앉으며 만두 모양으로 변한다.
   - 붙을 때는 만두가 물방울로 풀리고, 노치 끝에 닿아 버티다 스며든 뒤 봇 자리가 출렁인다. 눈 크기는 노치 봇 눈으로 천천히 바뀐다.
   - 작업 중, 승인 대기 몸 색을 전환 내내 유지한다.
   - 전환 중에도 노치 전체 모양(아래 둥근 모서리, 위쪽 오목 곡선)을 그려 전환 전후 모양이 이어지게 한다.
2. 메뉴바 토토 모양과 상태 표시 (작업 중 합의로 추가)
   - 몸을 원에서 둥근 만두 모양으로 바꾸고 메뉴바 높이를 다 쓰도록 키운다. 아이콘 폭은 몸에 맞게 42칸에서 20칸으로 줄인다.
   - 토토 눈을 세로로 긴 알약(폭:높이 약 1:2.3)에서 둥근 쪽(약 1:1.6)으로 바꾼다(메뉴바 토토, 노치 봇, 전환, 앱 아이콘).
   - 확인하지 않은 완료는 사각형 점 대신 민트 초록 몸 색으로 보여 준다(상단바 토토만).
   - 졸리면 몸이 85% 높이로, 잠들면 74% 높이와 110% 폭으로 납작해진다.
   - 표시 위치 메뉴 이름을 "상단바", "노치"로 바꾼다.
3. 버그 수정 (작업 중 발견)
   - 노치로 붙은 뒤 메뉴바 토토가 잠깐 다시 보이던 문제
   - 노치 → 메뉴바 전환이 메뉴바 아이콘 위치를 너무 일찍 읽어 생략되던 문제
   - 노치 봇 설정 메뉴가 메뉴바에 걸려 첫 항목이 잘리던 문제
4. 셔틀콕 미니게임 제거 (이슈 #75와 별개 요청)

### 후속 (이번 PR 범위 밖, 이슈 #75에 남김)

1. 펼친 노치 상호작용 개선
   - 펼친 노치를 닫는 방법을 늘린다(제안: 봇을 다시 누름, Esc, 마우스가 펼친 노치 밖으로 나간 뒤 잠시 지나면 자동으로 접힘).
2. 노치 봇 반응 추가 (제안)
   - 마우스를 봇 위에 올리면 눈이 살짝 커지며 봇을 바라본다.
   - 봇을 누르는 순간 눈이 납작해졌다가 돌아온다.
   - 작업이 끝나면 지금의 웃음에 더해 작게 한 번 튀어 오른다.
   - 승인 대기가 시작되면 눈을 크게 뜨고 좌우로 한 번 두리번거린다.

### 제외

- Claude, 그림 캐릭터의 메뉴바 동작 변경
- 랜딩 페이지와 파비콘의 토토 모양, 눈 반영
- 펼친 노치 크기와 내용 구성 변경
- 노치가 없는 화면 지원 방식 변경

## 설계 결정

- 파일 구조와 로직의 책임
  - 물방울 전환은 새 창 컨트롤러(`apps/macos/Sources/Desktoto/PlacementTransitionController.swift`)가 맡는다. 노치부터 메뉴바 아이콘 자리까지 덮는 투명 창을 잠시 띄워 그 위에서 재생하고, 끝나면 창을 닫는다.
  - 그리기는 `MenuBarIcon` 모듈의 새 SwiftUI 뷰(`PlacementTransitionView.swift`)가 맡는다. SwiftUI `Canvas`의 흐림과 투명도 경계 자르기(`alphaThreshold`)로 노치 몸통과 물방울이 끈적하게 이어지게 그린다.
  - 위치, 크기, 찌그러짐을 시간에 따라 계산하는 함수는 AppKit 없이 순수 값 계산으로 두어 테스트할 수 있게 한다(`PlacementTransitionMotion.swift`). 랜딩 데모의 `createDetachMotion`, `createAttachMotion`을 옮긴다.
  - 펼친 노치 닫기와 봇 반응은 기존 `NotchBotWindowController`와 `NotchBotView`(`NotchBotModel`)에 상태를 더한다.
- 상태와 데이터 흐름
  - `AppDelegate`의 `.selectPlacement`가 바로 `applyPlacement()`를 부르던 흐름을, 전환 컨트롤러가 애니메이션을 끝낸 뒤 부르도록 바꾼다.
  - 노치 → 메뉴바: 메뉴바 아이콘을 먼저 보이지 않는 상태로 자리만 잡아 도착 좌표를 얻고, 애니메이션이 끝나면 토토를 보이게 한다.
  - 메뉴바 → 노치: 메뉴바 아이콘 좌표에서 출발하고, 출발 순간 아이콘을 숨긴다.
- 선택한 방식과 이유
  - 노치 봇 창은 메뉴바보다 위 층이라 전환 창도 같은 층에 띄워 메뉴바 위를 지나가게 한다.
  - 전환 중에는 클릭을 통과시켜 다른 앱 사용을 막지 않는다.
- 예외 처리
  - 노치가 없는 화면이거나 메뉴바 아이콘 좌표를 못 얻으면 애니메이션 없이 바로 바꾼다.
  - 움직임 줄이기 설정(손쉬운 사용)이 켜져 있으면 애니메이션 없이 바로 바꾼다.
  - 전환 중에 다시 표시 위치를 바꾸면 진행 중인 애니메이션을 끝 상태로 건너뛰고 새 전환을 시작한다.

## 완료 조건

- AC-1: 노치 → 메뉴바 전환 때 봇이 늘어나 끊기고 튀어 가서 메뉴바 토토로 바뀌며, 끝나면 메뉴바 아이콘이 정상 동작한다.
- AC-2: 메뉴바 → 노치 전환 때 토토가 튀어 와 노치에 빨려 붙고, 끝나면 노치 봇이 정상 동작한다.
- AC-3: 전환 중 노치 폭이 캐릭터 위치를 따라 바뀌고, 끝난 뒤 노치 모양(오목 곡선 포함)이 튀지 않는다.
- AC-4: 움직임 줄이기 설정이나 노치 없는 화면에서는 애니메이션 없이 바로 바뀐다.
- AC-5: 펼친 노치를 추가한 방법(봇 다시 누름, Esc, 자동 접힘)으로 닫을 수 있다.
- AC-6: 봇 반응(올림, 누름, 완료, 승인 대기)이 합의한 대로 보이고, 기존 시선, 깜빡임, 졸음, 웃음이 깨지지 않는다.
- AC-7: `swift build`, `swift test`가 통과하고 전환 위치 계산 테스트가 있다.

## 미결정 사항

- 펼친 노치 자동 접힘: 마우스가 펼친 노치 밖으로 나간 뒤 몇 초 뒤에 접을지, 자동 접힘 자체를 넣을지. 구현 전에 정해야 한다.
- 봇 반응 네 가지의 구체적인 모양과 세기. 구현하며 실제 화면을 보고 조정한다.

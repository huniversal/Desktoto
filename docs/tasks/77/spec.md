# 작업 명세: [Feat] 랜딩 페이지에 바뀐 토토 캐릭터 반영

## 연결 정보

- 이슈: #77 / https://github.com/huniversal/Desktoto/issues/77
- 브랜치: feat/landing-character/#77
- specRevision: 1
- 대상 ai-run 원본: N/A (#75에서 바꾼 Desktoto 자체 캐릭터를 소개하는 작업)

## 목적

#75에서 토토의 모양과 상태 표현, 노치와 상단바 사이 물방울 전환이 바뀌었다.
지금 히어로는 문구 아래에 작은 Mac 목업이 따로 놓여 있어 상단바의 작은 움직임이 잘 보이지 않는다.
첫 화면 전체를 히어로로 쓰고, 카메라가 토토를 확대해 따라가는 연출로 바뀐 캐릭터를 크게 보여 준다.
참고 레퍼런스는 https://www.apple.com/kr/iphone-duo/ 의 전체 화면 히어로다.

## 작업 범위

### 포함

- 히어로를 첫 화면 전체(너비 100%, 높이 100svh)로 바꾸고, Mac 화면 데모를 그 배경으로 깔기
- 페이지를 열면 자동으로 재생하는 카메라 연출
  1. 노치의 토토(작업 중 몸 색)를 크게 확대해 화면 가운데에 잡음
  2. 토토가 물방울처럼 노치에서 떨어져 상단바로 이동하는 동안 확대한 채로 따라감
  3. 토토가 상단바에 자리 잡으면 잠깐 멈췄다가 천천히 줌아웃
  4. Mac 화면 전체가 보이면 반투명 막이 깔리고 히어로 제목, 리드, 다운로드 버튼이 나타남
- 막이 깔린 뒤에도 막 아래에서 기존 상태 데모가 계속 은은하게 반복됨
- 반투명 막은 라이트와 다크 모드에서 각각 배경색 기준으로 텍스트가 잘 읽히는 정도로 덮음
- 연출 중에는 막과 텍스트를 숨김
- 히어로 데모와 상태 섹션의 토토를 #75 기준으로 맞춤: 둥근 만두 모양과 큰 둥근 눈, 확인하지 않은 완료는 민트 초록 몸 색, 졸리거나 잠들면 납작한 몸
- 표시 위치 명칭을 상단바와 노치로 맞추고, 남아 있는 셔틀콕 미니게임 문구가 있으면 정리
- 움직임 줄이기 설정(`prefers-reduced-motion`)에서는 카메라 연출 없이 처음부터 전체 화면과 막, 텍스트를 보여 줌

### 제외

- 스크롤에 맞춰 진행하는 연출 (자동 재생으로 결정)
- 히어로 아래 섹션 구성 변경 (캐릭터 표현 맞춤만 함)
- 앱 동작 코드 변경
- 링크 미리보기 이미지(`og-v2.png`) 교체

## 설계 결정

- 파일 구조와 로직의 책임
  - 기존처럼 `apps/web/index.html` 한 파일의 CSS, 마크업, 스크립트를 고친다.
  - `header.hero`를 전체 화면 스테이지로 바꾸고, 문구 묶음은 스테이지 위에 겹치는 레이어로 둔다.
- 상태와 데이터 흐름
  - 카메라는 데모를 감싼 요소에 `transform`(scale, translate)을 적용해 움직인다. 기존 노치와 물방울 전환 재생 흐름 앞에 카메라 단계를 붙이고, 전환 중 토토 위치를 읽어 카메라 목표점으로 쓴다.
  - 연출이 끝나면 카메라는 전체 화면에 고정되고, 이후 데모 반복은 카메라를 움직이지 않는다.
- 선택한 방식과 이유
  - 자동 재생: 첫 화면 하나로 끝나서 구현이 단순하고 모바일에서도 안정적이다.
  - `transform` 기반 카메라: 레이아웃을 다시 계산하지 않아 부드럽다.
- 예외 처리
  - 화면이 좁아 데모가 잘리면 데모는 화면을 덮도록 맞추고 텍스트 가독성을 막으로 확보한다.
  - 탭이 숨겨졌다가 돌아와도 연출이 꼬이지 않게 최종 상태로 맞춘다.

## 완료 조건

- AC-1: 첫 화면이 너비와 높이를 꽉 채운 히어로로 보이고, Mac 화면 데모가 그 배경이다.
- AC-2: 페이지를 열면 노치 확대, 토토 따라가기, 줌아웃 순서로 자동 재생된다.
- AC-3: 줌아웃 뒤 반투명 막 위에 제목, 리드, 다운로드 버튼이 읽히게 나타나고, 막 아래 데모는 계속 움직인다.
- AC-4: 토토 모양과 상태 표현이 #75의 앱과 같다 (만두 모양, 둥근 눈, 민트 초록 완료, 납작한 졸음).
- AC-5: 움직임 줄이기 설정에서는 연출 없이 최종 화면이 바로 보인다.
- AC-6: 데스크톱과 모바일 너비, 라이트와 다크 모드에서 가로 스크롤 없이 텍스트가 읽힌다.

## 검증 방법

| 완료 조건 | 확인 방법 | 기대 결과 |
|---|---|---|
| AC-1 | 로컬 서버로 열어 데스크톱 너비에서 확인 | 히어로가 첫 화면 전체를 채움 |
| AC-2 | 새로고침 후 화면 녹화로 프레임 확인 | 연출 단계가 순서대로 재생됨 |
| AC-3 | 연출 종료 뒤 스크린샷 | 텍스트가 읽히고 데모가 움직임 |
| AC-4 | 앱 실행 화면과 랜딩 데모를 나란히 비교 | 모양과 색 일치 |
| AC-5 | 브라우저에서 reduced motion 에뮬레이션 | 최종 화면이 바로 표시됨 |
| AC-6 | 375px 너비와 다크 모드로 확인 | 가로 스크롤 없음, 텍스트 읽힘 |

## 미결정 사항

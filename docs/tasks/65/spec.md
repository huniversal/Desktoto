# 작업 명세: [Feat] 메뉴바 캐릭터 선택 및 치이카와, 하치와레, 우사기 추가

## 목적

메뉴바 캐릭터를 Claude 픽셀 캐릭터 외에 먼작귀 캐릭터(치이카와, 하치와레, 우사기)로 고를 수 있게 한다.
그림 캐릭터는 원작 GIF에서 뽑은 프레임으로 대기 중과 작업 중에 자연스럽게 움직이고, 캐릭터마다 배경 장면과 소리가 다르다.
테스트 워크트리(`feat/sandbox/test`)에서 만든 동작을 develop의 새 구조(#61 시선과 쉬는 동작, #62 셔틀콕 게임) 위로 옮긴다.
함께 승인 대기 물음표를 빨간색으로 바꾼다.

## 작업 범위

### 포함

- 설정: `IconCharacter`(claude, chiikawa, hachiware, usagi) 저장, 우클릭 메뉴에 "캐릭터" 하위 메뉴(Claude, 치이카와, 하치와레, 우사기)
- 그림 캐릭터 렌더링: GIF에서 뽑아 배경을 지운 프레임(base64 PNG)을 캔버스에 그린다. Claude는 지금 그대로 사각형으로 그린다.
- 대기 중: 캐릭터마다 대기 클립 여러 개를 50ms 간격으로 돌리고, 최소 4초 뒤 클립이 끝나는 순간 다른 클립으로 무작위 전환한다(같은 클립 연속 금지).
  - 치이카와 8개, 하치와레 3개, 우사기 5개
- 작업 중: 치이카와는 통통 뛰며 오른쪽으로 이동하고 들판이 흘러간다. 하치와레와 우사기는 제자리에서 춤춘다. 상반신이 캔버스 높이를 채우도록 확대한다.
- 배경: 애니 장면을 깐다. 치이카와 들판, 하치와레 문 앞, 우사기 숲속. 캔버스 모서리는 둥글게 자른다.
- 크기: 그림 캐릭터는 메뉴바 높이(노치 화면은 화면에서 직접 잰 값)로 그리고 위아래 여백은 1pt다.
- 작업 완료 소리: 치이카와, 하치와레, 우사기마다 다른 소리. Claude는 기본 Glass.
- 승인 대기 소리: 캐릭터마다 다른 소리. Claude는 기본 Ping. 소리는 사용자가 후보를 듣고 고른다.
- 승인 대기 물음표를 빨간색으로 바꾼다(모든 캐릭터).

### 제외

- 그림 캐릭터의 마우스 시선, 표정, 하품, 쉬는 동작(잠, 낚시 등 8가지). 그림 캐릭터는 대기 클립만 돌린다.
- 셔틀콕 게임 오버레이의 캐릭터 교체. 게임은 어떤 캐릭터를 골라도 Claude 캐릭터로 한다.
- 메뉴바가 붐빌 때 macOS가 아이콘을 줄여 그리는 현상의 원인 조사와 대응
- README, 랜딩 페이지 수정

## 설계 결정

- 파일 구조와 로직의 책임
  - `DesignSystem/Appearance/Appearance.swift`: `IconCharacter`. Preferences가 MenuBarIcon에 의존하지 않도록 DesignSystem에 둔다.
  - `MenuBarIcon/CharacterArt.swift`: 자세(`ArtPose`), 대기 클립(`IdleClip`), 무작위 전환(`IdleClipPicker`, `IdlePlayback`), 작업 중 보일 범위
  - `MenuBarIcon/CharacterArtData.swift`: 프레임 base64 데이터
  - `MenuBarIcon/SceneBackdrop.swift`: 배경 장면과 들판 흐름
  - `MenuBarIcon/IconScene.swift`: `IconFrame.idle(clip:frame:)` 추가, 그림 캐릭터 배치(`ImagePlacement`)와 배경 자리(`BackdropPlacement`)
  - `MenuBarIcon/IconRenderer.swift`, `IconImageSet.swift`, `IconTiming.swift`: 그리기, 미리 그린 이미지, 갱신 주기
  - `Desktoto/MenuBarIconController.swift`: 캐릭터에 따라 Claude의 시선과 쉬는 동작, 또는 그림 캐릭터의 대기 클립 중 하나만 켠다.
  - `Desktoto/AppDelegate.swift`: 캐릭터 선택 처리, 완료 소리와 승인 대기 소리
- 상태와 데이터 흐름
  - 캐릭터는 `AppSettings.iconCharacter`에 저장하고 `IconState.character`로 컨트롤러에 넘긴다.
  - 그림 캐릭터일 때 컨트롤러는 쉬는 동작(`rest`)을 무시하고, 작업 중이 아니면 대기 클립 타이머를 돌린다.
  - 캐릭터가 바뀌면 이미지 높이가 달라지므로 이미지 묶음을 새로 만들고, 돌던 타이머를 새 주기로 다시 시작한다.
- 선택한 방식과 이유
  - 그림은 리소스 번들 대신 코드에 base64로 넣는다. 패키징 스크립트가 SwiftPM 리소스 번들을 앱에 복사하지 않기 때문이다.
  - 소리 파일은 `apps/macos/Resources`에 두어 앱 번들 `Contents/Resources`로 복사되게 한다.
  - 대기 클립은 고유 프레임만 미리 그리고, 50ms 칸은 순서표로 프레임에 대응시켜 메모리를 아낀다.
- 예외 처리
  - 소리 파일을 찾지 못하면(앱 번들이 아닐 때) 기본 소리(Glass, Ping)를 낸다.
  - 저장된 캐릭터 값을 읽지 못하면 Claude로 돌아간다.

## 완료 조건

- AC-1: 우클릭 메뉴의 "캐릭터"에서 Claude, 치이카와, 하치와레, 우사기를 고를 수 있고, 고른 값이 저장되어 앱을 다시 켜도 유지된다.
- AC-2: Claude를 고르면 develop과 같은 동작(시선, 표정, 쉬는 동작, 달리기)을 한다.
- AC-3: 그림 캐릭터는 대기 중에 대기 클립을 돌리고, 최소 4초 뒤 클립이 끝날 때만 다른 클립으로 바뀌며 같은 클립이 연달아 나오지 않는다.
- AC-4: 그림 캐릭터는 작업 중에 작업 중 동작으로 바뀌고 상반신이 캔버스 높이를 채운다. 치이카와는 들판이 흘러간다.
- AC-5: 그림 캐릭터는 각자의 애니 장면 배경 위에 그려지고, 위아래 1pt 여백을 둔다.
- AC-6: 작업이 끝나면 캐릭터별 완료 소리가, 승인 대기가 생기면 캐릭터별 승인 대기 소리가 난다.
- AC-7: 승인 대기 물음표가 빨간색이다.
- AC-8: 그림 캐릭터를 골라도 셔틀콕 게임이 지금처럼 동작한다.

## 미결정 사항

- 캐릭터별 승인 대기 소리: 후보를 들려주고 사용자가 고른다. 고르기 전까지는 구현을 막지 않는다(파일만 교체).
- 원작 그림과 소리를 공개 배포 앱에 넣어도 되는지: 저작권 판단은 사용자 결정이 필요하다. 구현은 막지 않지만 배포 전에 정해야 한다.

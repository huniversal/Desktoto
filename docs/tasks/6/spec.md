## 목적

Claude와 Codex의 계정 사용량을 원본과 같은 소스, 선택 규칙, 실패 처리로 제공한다.
ai-run을 읽기 전용 기준으로 삼아 제품 동작은 유지하고 내부 구조와 테스트 가능성만 재설계한다.
외부 앱의 현재 공개 문서나 새 API에 맞춘 기능 변경은 이번 범위가 아니다.

## 설계 결정

- 파일 구조와 로직의 책임: 모델은 `apps/macos/Sources/Domain`, 수집과 캐시와 선택은 `apps/macos/Sources/UsageMonitoring`, 외부 접근은 `apps/macos/Sources/Boundaries`, 가짜 구현은 `apps/macos/Sources/TestSupport`에 둔다. 테스트는 `apps/macos/Tests/UsageMonitoringTests`를 추가하고 모델과 경계 검증은 해당 모듈에 둔다. `apps/macos/Package.swift`에는 실제 테스트 타깃만 추가한다. 파일별 상세 이름은 구현 승인 전에 제시한다.
- 기존 경계의 부족한 부분: 현재 ProcessRunner는 짧은 명령과 pid 확인만 지원한다. 장기 프로세스는 보조 경계 ProcessLauncher와 RunningProcess로 분리하여 stdin 쓰기, stdout AsyncStream, 종료와 취소를 지원한다. FileSystem에는 캐시의 비재귀 목록, 파일 크기와 실행 가능 여부 확인에 필요한 최소 기능을 보강한다. 기능 모듈끼리 import하지 않는다.
- 상태와 데이터 흐름: 소스별 원시 값과 캐시를 수집 서비스가 소유한다. 통합 조회에서 TimeSource의 현재 시각으로 초기화 보정과 최신값 선택을 수행한다. 프로세스 요청과 출력 처리의 소유자를 하나로 두고 취소, 비활성화, 재실행 뒤 이전 프로세스 응답이 새 상태를 덮지 않게 한다. Swift 6 격리 방식과 경계 시그니처는 구현 전에 구체화한다.
- 원본 유지: 경로, 후보 개수, 파싱 키, 시간 상수와 오류 시 대체 흐름은 원본 동작 문서를 따른다. 두 소스는 한도별 병합 없이 전체 스냅샷으로 비교한다. Codex 실패 뒤에도 마지막 성공 값은 유지한다.
- 예외 처리: 파일 없음, 권한 거부, 잘림, 형식 변경, 압축 오류는 해당 소스의 값 없음으로 처리한다. 다른 소스의 정상 값을 유지한다. 인증과 설정을 고쳐 복구하려 하지 않는다.
- 앱 연결 계약: 조회, Codex 갱신 요청(최소 간격 전달), 활성화 여부, 변경 통지, stop을 제공한다. 패널 열림 30초와 닫힘 300초 주기는 #11에서 적용한다.

## 완료 조건

- AC-1: 선택적 두 한도와 수신 시각을 표현하고 원본과 같은 600초 기준의 낡은 값 문구를 반환한다.
- AC-2: statusLine json과 Codex jsonl을 숨김 제외 재귀 탐색하고 최신 수정 파일 5개 중 첫 유효 값을 선택한다. 값이 없으면 nil이다.
- AC-3: statusLine의 used_percentage, Codex 기록의 used_percent와 window_minutes, 데스크탑 utilization, RPC usedPercent와 windowDurationMins를 원본 키대로 읽는다. 비율을 0...1로 제한하고 Codex 창 600분 이하와 7200분 이상만 분류한다.
- AC-4: Codex 기록의 최신 token_count를 64KiB, 512KiB, 4MiB 순서로 찾는다. 기록 시각과 수정 시각 캐시(nil 포함), 방문하지 않은 캐시 제거가 원본과 같다.
- AC-5: Claude 캐시의 바로 아래 _0 파일, 크기 500...65,536바이트, 최신 600개 제한과 키 패턴을 지킨다. 백그라운드 탐색, 중복 방지, 120초 제한, 경로 소실과 수정 시각 캐시가 원본과 같다.
- AC-6: Simple Cache 머리와 키를 검증하고 평문 JSON 또는 zstd 첫 프레임을 읽는다. 손상, 잘림, 해독 결과 1MiB 초과를 거부하며 정상 프레임 뒤 메타데이터는 해독하지 않는다. ISO 날짜 소수 초 제거와 epoch 날짜를 원본대로 처리한다.
- AC-7: 원본 7개 실행 경로와 PATH 보강을 사용하고 initialize, initialized, account/rateLimits/read 순서를 지킨다. 개행 조각을 보관하며 ID 응답, 오류, 갱신 알림을 구별한다.
- AC-8: 중복 요청과 최소 간격을 제한하고 요청 15초 제한, 파일 없음 600초 대기, 기타 실패 120초 대기, 성공 뒤 60초 유휴 종료를 적용한다. 실패해도 마지막 성공 값은 남긴다.
- AC-9: 비활성화와 stop에서 프로세스와 대기 요청을 정리한다. 종료된 프로세스에 쓰거나 종료와 늦은 출력이 경합해도 앱이 종료되거나 이전 결과가 새 상태를 덮지 않는다.
- AC-10: 도구별 최신 수신 시각의 소스 전체 값을 선택하고 시각 없음은 distantPast로 비교한다. 읽을 수 있는 도구만 Claude, Codex 순서로 반환한다. 초기화 시각이 now 이하인 한도는 비율 0과 시각 nil이며 캐시를 재사용해도 다시 계산한다.
- AC-11: 합성 데이터와 가짜 파일, 시간, 프로세스만으로 성공과 실패를 테스트한다. 실제 사용자 데이터나 인증 정보를 테스트와 Git에 넣지 않는다.
- AC-12: 실제 Mac에서 ai-run과 같은 입력에 대한 사용 비율, 초기화 시각, 수신 시각과 대체 소스 결과를 비교하고 환경과 결과를 기록한다. 빌드나 단위 테스트만으로 동등성 완료를 선언하지 않는다.

## 미결정 사항

- 구현 파일과 actor, AsyncStream 사용 범위는 사용자 승인 완료. 시간은 TimeSource, 비동기 대기는 주입 가능한 sleep 클로저로 제어한다.
- 원본의 버그로 확정한 사항은 현재 없음. 의심 동작이 발견되면 재현 근거와 영향을 이 절에 추가하고 사용자와 결정한다.
- AC-12의 실제 입력을 이용한 수집 계층 비교를 완료했다. 원본 수집 소스를 임시 실행 도구로 컴파일해 새 수집기와 비교했으며, 설치된 두 앱의 화면을 나란히 실행한 UI 동등성 확인은 #11 조립 이후 범위다.

## 구현과 검증 기록

- 환경: macOS 27.0.1, Xcode 27.1 (27A9275).
- `swift build`: 성공, 최종 로그에 경고 없음.
- `swift test`: 전체 151개 통과. 이 중 UsageMonitoringTests 25개.
- 검증한 항목: 파싱, 비율 제한, 초기화와 낡은 값 경계, JSON-RPC 분할 출력과 초기화 재사용, 최소 조회 간격, 파일 없음 600초 대기, 타임아웃과 120초 대기, 취소와 stop, 유휴 종료, 실패 뒤 성공 값 유지, 파일 후보 5개 제한, 백그라운드 캐시 탐색과 재사용, 소스 전체 값 선택.
- 임시 폴더의 파일 크기와 비재귀 목록, 실행 가능 여부 확인, 실제 `/bin/cat`의 stdin과 stdout 및 종료를 검증했다. 사용자 세션 파일과 인증 정보는 테스트에 쓰지 않았다.
- 추가 검증: 캐시 탐색 최신 600개와 부적합 후보 제외, 실패 후 119초와 120초 경계, 4MiB 범위까지 로그 확대 읽기, 파싱 실패 캐시와 수정 후 재읽기, zstd 해독 1MiB 허용과 1바이트 초과 거부, 잘못된 초기화 응답 거부, 콜백 대기 중 알림과 후속 조회 처리.
- 코드 재대조 결과 보완: 콜백을 기다리며 출력 소비를 막던 문제를 별도 메인 actor 통지로 수정하고, 유휴 타이머에 조회별 세대 번호를 추가했다. 매 조회의 실행 파일 확인과 JSON-RPC result 객체 검증도 원본에 맞췄다.
- 리뷰 후 수신 순서 보완: 정상 응답의 저장을 continuation 재개 전으로 옮겨 후속 알림 덮어쓰기와 EOF 직전 응답 손실을 수정하고 두 회귀 테스트를 추가했다.
- 실제 입력 비교 결과는 [동등성 검증 기록](verification.md)에 정리했다. 네 소스가 모두 가용했고 원본과 사용 비율, 초기화 시각이 일치했다. 파일 소스의 수신 시각도 일치했다.
- 실시간 응답 수신 시각은 각 응답을 받은 시점이므로 서로 동일한 시각을 요구하지 않는다. 설치된 앱의 UI와 패널 타이머 동작, 실제 환경의 권한 거부와 네트워크 단절 상황은 이번 수집 계층 검증에 포함하지 않았다. 오류와 취소는 합성 입력으로 검증했다.
- 초기 기본 샌드박스 빌드는 Swift 모듈 캐시 접근 제한으로 실패했다. 승인된 실행으로 재시도하여 위 결과를 얻었다.
